O que é

O Floci roda serviços com a cara da AWS na sua máquina, para desenvolvimento, testes e CI. Você aponta o AWS CLI, o SDK, o Terraform, o CDK, o OpenTofu ou a sua suíte de testes para http://localhost:4566 e continua trabalhando como se fosse a AWS. Não precisa de conta na AWS, token de autenticação nem plano pago.

Ele nasceu como substituto direto do LocalStack Community: segundo o README, o LocalStack Community foi encerrado em março de 2026, passou a exigir token e congelou as atualizações de segurança. A migração é trocar a imagem Docker; a porta, as credenciais e as variáveis de ambiente do LocalStack continuam funcionando.

A maioria dos serviços roda dentro do próprio processo. Os que precisam de fidelidade sobem containers Docker reais: Lambda, RDS (PostgreSQL, MySQL e MariaDB), ElastiCache (Valkey), MSK (Redpanda), ECS, EC2, EKS (k3s), OpenSearch, DocumentDB (MongoDB), Neptune e CodeBuild. A mesma família tem emuladores para Azure (floci-az, porta 4577), GCP (floci-gcp, 4588) e Oracle Cloud (floci-oci, 4599).

Principais recursos

  • Cobertura ampla: S3, SQS, SNS, DynamoDB (com Streams), Lambda, IAM, STS, KMS, Secrets Manager, SSM, API Gateway REST e v2, Cognito, EventBridge, Step Functions, CloudFormation, CloudWatch, SES, Kinesis, Athena (DuckDB), Glue, Route53, CloudFront, WAF, Organizations, Cost Explorer e muitos outros.
  • Leve: o README cita início em ~24 ms, ~13 MiB de memória ociosa e imagem Docker de ~90 MB, contra ~3,3 s, ~143 MiB e ~1 GB do LocalStack. Há também um binário nativo (floci-aws) para Linux, macOS e Windows, que dispensa o Docker.
  • Console web em http://localhost:4566/_floci/ui para ver os recursos criados. Dá para trocar por outro console compatível.
  • Persistência configurável: memory, persistent, hybrid e wal.
  • Várias contas isoladas: um AWS_ACCESS_KEY_ID de 12 dígitos vira o ID da conta, e AssumeRole entre contas funciona.
  • Testcontainers para Java, Node.js, Python e .NET (Go em andamento).
  • Mais de 2.500 testes de compatibilidade com os SDKs Java, Node, Python e Go, o AWS CLI, Terraform, OpenTofu e CDK.
  • Qualquer região publicada da AWS funciona, em todas as partições.

Pré-requisitos

  • Docker: para a imagem e para os serviços que usam containers reais (Lambda, RDS etc.), que precisam do socket do Docker. Sem Docker, use o binário nativo, mas esses serviços não sobem.
  • Opcional: a CLI floci, o AWS CLI e os SDKs da AWS que você já usa.

Instalação

Pela CLI oficial (recomendado)

A CLI (floci-io/floci-cli) inicia, para e configura os emuladores.

# macOS / Linux (Homebrew)
brew install floci-io/floci/floci

# Linux / macOS (script)
curl -fsSL https://floci.io/install.sh | sh

# Windows (PowerShell)
iwr https://floci.io/install.ps1 | iex

Depois:

floci start           # sobe o emulador AWS
eval $(floci env)     # exporta as variáveis AWS_* apontando para o emulador

Docker Compose

Crie um compose.yaml:

services:
  floci:
    image: floci/floci:latest
    ports:
      - "4566:4566"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock   # para Lambda, RDS, ECS, console web etc.

docker compose up
export AWS_ENDPOINT_URL=http://localhost:4566
export AWS_DEFAULT_REGION=us-east-1
export AWS_ACCESS_KEY_ID=test
export AWS_SECRET_ACCESS_KEY=test

Docker run (com os serviços em container)

docker run -d --name floci \
  -p 4566:4566 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -u root \
  floci/floci:latest

Vindo do LocalStack

# antes
image: localstack/localstack
# depois
image: floci/floci:latest
# ou, se os scripts de init usam AWS CLI ou boto3
image: floci/floci:latest-compat

Variáveis como LOCALSTACK_HOST, PERSISTENCE=1 e DEBUG=1 são traduzidas sozinhas. Scripts em /etc/localstack/init/ rodam sem mudança.

Comandos e uso

aws s3 mb s3://my-bucket
aws dynamodb create-table \
  --table-name demo-table \
  --attribute-definitions AttributeName=pk,AttributeType=S \
  --key-schema AttributeName=pk,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST
aws dynamodb list-tables

# sem exportar AWS_ENDPOINT_URL:
aws --endpoint-url http://localhost:4566 s3 ls

No código (Python / boto3):

import boto3
client = boto3.client("ssm", endpoint_url="http://localhost:4566",
                      region_name="us-east-1",
                      aws_access_key_id="test", aws_secret_access_key="test")

Nos testes (Testcontainers):

npm install --save-dev @floci/testcontainers   # Node.js
pip install testcontainers-floci               # Python
# Java: io.floci:testcontainers-floci (Maven Central)

Contas isoladas:

AWS_ACCESS_KEY_ID=111111111111 aws sqs create-queue --queue-name orders
AWS_ACCESS_KEY_ID=222222222222 aws sqs create-queue --queue-name orders

Configurações principais (variáveis FLOCI_*):

Variável Padrão Para quê
FLOCI_PORT 4566 Porta da API
FLOCI_DEFAULT_REGION us-east-1 Região padrão
FLOCI_STORAGE_MODE memory memory, persistent, hybrid ou wal
FLOCI_STORAGE_PERSISTENT_PATH ./data Pasta dos dados persistidos
FLOCI_HOSTNAME (vazio) Nome do serviço no Compose (ex.: floci), para as URLs devolvidas apontarem para o container certo

Tags da imagem: latest (estável), x.y.z (versão fixa), latest-compat (com AWS CLI e boto3), latest-baseline (ARM64 antigo, como Raspberry Pi 4) e nightly. Sai versão estável todo dia 15 e no último dia de cada mês.

Quando usar

  • Desenvolver e testar apps que usam AWS sem gastar com a conta nem depender da internet.
  • Rodar testes de integração no CI com um emulador que sobe em milissegundos.
  • Testar Terraform, OpenTofu ou CDK localmente antes de aplicar na AWS de verdade.
  • Substituir o LocalStack Community sem precisar de token.
  • Simular cenários com várias contas (Organizations, AssumeRole entre contas).

Observações

  • É um emulador, não a AWS. Alguns serviços são só stubs: Bedrock Runtime devolve respostas fictícias, e Textract e Transcribe não processam nada de verdade. O FIS só simula o experimento, sem injetar falhas. Confira a fidelidade de cada serviço na lista de serviços antes de confiar nos resultados.
  • Socket do Docker: montar /var/run/docker.sock (e rodar com -u root) dá ao container controle total do Docker da máquina. Use só em ambiente de desenvolvimento.
  • Não exponha na internet: por padrão, qualquer credencial não vazia é aceita. A verificação de acesso do S3 fica desligada (FLOCI_SERVICES_S3_ENFORCE_AUTH=false).
  • No modo memory, que é o padrão, os dados somem quando o container para.
  • A imagem antiga hectorvent/floci não recebe mais atualizações. Use floci/floci.
