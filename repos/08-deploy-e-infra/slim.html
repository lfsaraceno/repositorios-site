O que é

O Slim (antigo DockerSlim) é uma ferramenta de linha de comando para inspecionar, otimizar e depurar containers. O comando mais usado, build, sobe um container temporário a partir da sua imagem, observa o que a aplicação realmente usa enquanto roda (análise estática e dinâmica) e gera uma imagem nova só com o necessário. Você não precisa trocar a imagem base, o gerenciador de pacotes nem otimizar o Dockerfile à mão.

Além de diminuir o tamanho, isso reduz a superfície de ataque, e o Slim gera automaticamente perfis de segurança Seccomp e AppArmor a partir do comportamento observado. Já foi usado com Node.js, Python, Ruby, Java, Go, Rust, Elixir e PHP sobre Ubuntu, Debian, CentOS, Alpine e Distroless. Exemplos do README: Node.js de 432 MB para 14 MB, Python de 916 MB para 27,5 MB e Go de 700 MB para 1,56 MB.

Também serve para entender imagens de terceiros: o xray mostra o que tem em cada camada e reconstrói o Dockerfile da imagem (Dockerfile.reversed). O projeto é sandbox da CNCF.

Principais recursos

  • build: minifica a imagem observando a aplicação em execução, com sondagem HTTP automática.
  • xray: análise estática da imagem, camada por camada, com engenharia reversa do Dockerfile.
  • lint: verifica instruções do Dockerfile.
  • debug: anexa um container sidecar de depuração a um container mínimo (sem shell), no Docker ou no Kubernetes.
  • profile: gera relatório e perfil Seccomp sem criar a imagem otimizada.
  • Geração automática de perfis Seccomp e AppArmor.
  • merge, registry (pull, push, copy), images, appbom (dependências da aplicação) e vulnerability (EPSS).
  • Modo interativo com autocompletar ao rodar slim sem parâmetros.

Pré-requisitos

  • Docker instalado e em execução. O Slim conversa com o daemon pelo socket /var/run/docker.sock ou pelas variáveis DOCKER_HOST, DOCKER_TLS_VERIFY e DOCKER_CERT_PATH.
  • Binários oficiais para Linux (x86, ARM, ARM64) e macOS (Intel e Apple Silicon). Não há binário para Windows: no Windows, use a imagem Docker do Slim ou rode dentro do WSL.
  • Algumas análises avançadas dependem de recursos do kernel Linux.

Instalação

Script (Linux e macOS)

curl -sL https://raw.githubusercontent.com/slimtoolkit/slim/master/scripts/install-slim.sh | sudo -E bash -

Download manual (Linux)

curl -L -o ds.tar.gz https://github.com/slimtoolkit/slim/releases/download/1.40.11/dist_linux.tar.gz
tar -xvf ds.tar.gz
mv dist_linux/slim /usr/local/bin/
mv dist_linux/slim-sensor /usr/local/bin/

Para outras plataformas (Mac, Mac M1, Linux ARM e ARM64), veja os links na seção INSTALLATION do README. O pacote traz dois binários: slim (o app) e slim-sensor (coleta dados dos containers).

Homebrew

brew install docker-slim

Docker (recomendado no Windows)

docker pull dslim/slim
docker run -it --rm -v /var/run/docker.sock:/var/run/docker.sock dslim/slim build nome-da-sua-imagem

Atualizar

slim update

Comandos e uso

slim                                       # modo interativo, com sugestões e autocompletar
slim help                                  # lista comandos e flags globais
slim build my/sample-app                   # gera a imagem minificada my/sample-app.slim
slim build --http-probe=false minha/cli    # para ferramentas de linha de comando sem API HTTP
slim build --target archlinux:latest --tag archlinux:curl --http-probe=false --exec "curl checkip.amazonaws.com"   # imagem que só sabe rodar curl
slim build --include-path=/var/lib/nginx nginx   # força a inclusão de um caminho que a análise não detectou
slim xray my/sample-app                    # mostra o conteúdo de cada camada e reconstrói o Dockerfile
slim lint --target Dockerfile              # verifica o Dockerfile
slim profile my/sample-app                 # só analisa e gera o perfil Seccomp, sem nova imagem
slim debug mycontainer                     # abre um shell de depuração num container em execução
slim debug --runtime=k8s --pod=example-pod example-container   # o mesmo no Kubernetes

Por padrão, o build pausa e espera você interagir com o container temporário (as portas mapeadas aparecem no console) e depois pressionar Enter. Use --continue-after para mudar isso e integrar com os seus testes.

Usar o perfil Seccomp gerado (funciona com a imagem original e com a minificada):

docker run --security-opt seccomp:<pasta do slim>/.images/<ID_DA_IMAGEM>/artifacts/your-name-your-app-seccomp.json your-name/your-app

CI/CD

GitHub Actions, com a action da comunidade:

- uses: kitabisa/docker-slim-action@v1
  env:
    DSLIM_HTTP_PROBE: false
  with:
    target: IMAGE_NAME:latest
    tag: "slim"

O README também traz exemplos para Jenkins, GitLab (dind) e CircleCI usando a imagem dslim/slim.

Quando usar

  • Diminuir imagens Docker antes do deploy (no Coolify, no CapRover ou num registry) para economizar disco e banda e acelerar o pull.
  • Reduzir a superfície de ataque dos containers em produção e gerar perfis Seccomp sem conhecer syscalls.
  • Investigar por que uma imagem está grande ou entender uma imagem de terceiros (xray).
  • Depurar containers mínimos ou distroless, que não têm shell (debug).

Observações

  • Teste a imagem minificada antes de ir para produção. A análise só mantém o que viu sendo usado: arquivos carregados dinamicamente ou rotas que não foram acessadas podem ficar de fora. Use --http-probe-cmd, --include-path e --continue-after com os seus testes para cobrir isso.
  • Apps sem API HTTP exigem que você interaja manualmente com o container durante a análise.
  • Nginx com diretório temporário fora do padrão falha na imagem minificada; resolva com --include-path.
  • A última release publicada é a 1.40.11, de fevereiro de 2024. O repositório segue com commits (último em set/2026), mas sem versões novas.
  • O README tem um link para um portal SaaS (slim.dev), que é opcional; o CLI funciona sozinho.
