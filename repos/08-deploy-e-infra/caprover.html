O que é

O CapRover é um gerenciador de deploy de aplicações e bancos de dados, com servidor web embutido, para apps NodeJS, Python, PHP, ASP.NET, Ruby, Go, MariaDB, MySQL, MongoDB, Postgres, WordPress e outros. Por baixo ele usa Docker (Swarm), nginx, Let's Encrypt e NetData.

A proposta é dispensar conhecimento profundo de Docker ou nginx: você instala o CapRover em um servidor, aponta um domínio e passa a publicar apps pelo painel web ou pela CLI. Não há lock-in: se remover o CapRover, os apps continuam rodando.

Principais recursos

  • Painel web e CLI para automação e scripts.
  • Docker Swarm para containerização e clusterização.
  • nginx (com template personalizável) para balanceamento de carga.
  • HTTPS gratuito com Let's Encrypt.
  • Instalação de bancos (MariaDB, MySQL, MongoDB, Postgres) e apps por seleção em lista (one-click apps).
  • Deploy por captain-definition (arquivo na raiz do projeto), Dockerfile ou imagem pronta.
  • Sem lock-in: os apps seguem funcionando sem o CapRover.

Pré-requisitos

(Conforme o guia "Getting Started" da documentação oficial.)

  • Servidor com IP público (ou instalação local, com limitações de HTTPS), em AMD64 ou ARM64. Testado em Ubuntu 24.04.
  • Docker 25 ou superior instalado com as instruções oficiais (evite a instalação via snap).
  • Pelo menos 1 GB de RAM recomendado (512 MB pode não bastar para builds).
  • Um domínio com registro DNS wildcard (*.algo.seudominio.com) apontando para o IP do servidor, se quiser HTTPS.
  • Portas liberadas no firewall: 80/tcp, 443/tcp, 443/udp e 3000/tcp.

Instalação

  1. No servidor, libere as portas (exemplo para Ubuntu com ufw):
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 443/udp
ufw allow 3000/tcp
  1. Instale o CapRover:
docker run -p 80:80 -p 443:443 -p 3000:3000 -e ACCEPTED_TERMS=true -v /var/run/docker.sock:/var/run/docker.sock -v /captain:/captain caprover/caprover
  1. Crie o registro DNS do tipo A: *.algo.seudominio.com apontando para o IP do servidor.
  2. Instale a CLI na sua máquina e rode o assistente de configuração (recomendado em vez de usar o painel no primeiro acesso):
npm install -g caprover
caprover serversetup

O assistente pede o IP do servidor, o domínio raiz e um e-mail válido (usado no certificado SSL) e, ao final, pede para trocar a senha. O painel fica em http://IP_DO_SERVIDOR:3000 e a senha padrão inicial é captain42.

A documentação também indica instalação por one-click app no DigitalOcean.

Comandos e uso

caprover login      # faz login em um servidor CapRover (pode ter vários)
caprover deploy     # envia o app do diretório atual para o servidor

Para deploy, crie um arquivo captain-definition na raiz do projeto, por exemplo para Node:

{
  "schemaVersion": 2,
  "templateId": "node/24"
}

Quando usar

  • Publicar vários apps e bancos em uma única VPS com HTTPS automático.
  • Ter um "Heroku próprio" simples, com painel e CLI, sem aprender Kubernetes.
  • Substituir PaaS pagos para reduzir custo.

Observações

  • Troque a senha padrão captain42 imediatamente.
  • O README e o LICENSE indicam Apache 2.0 (o GitHub marca a licença como "NOASSERTION").
  • O front-end e a documentação ficam em repositórios separados (caprover-frontend e caprover-website).
  • Alternativa mais moderna e com mais recursos: veja o Coolify.
