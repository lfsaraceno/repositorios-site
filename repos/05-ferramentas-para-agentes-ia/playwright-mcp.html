Playwright MCP

Servidor MCP oficial da Microsoft que dá a LLMs o controle de um navegador via Playwright. O agente lê a página pela árvore de acessibilidade, sem depender de screenshots nem de modelo de visão.

O que é

O Playwright MCP expõe o Playwright como ferramentas MCP (browser_navigate, browser_click, browser_snapshot...). A cada ação, o agente recebe um snapshot estruturado da árvore de acessibilidade, com referências para mirar nos elementos. Por isso as ações são determinísticas, sem a ambiguidade de clicar por coordenadas num screenshot.

MCP ou CLI? O próprio README recomenda o Playwright CLI para agentes de código, porque gasta menos tokens: não carrega os esquemas das ferramentas nem árvores de acessibilidade enormes no contexto. O MCP continua melhor para fluxos longos e autônomos que precisam de estado contínuo e análise detalhada da página, como automação exploratória e testes que se corrigem sozinhos.

Principais recursos

  • Ferramentas principais: navegar, clicar, digitar, preencher formulários, arrastar, soltar arquivos, upload, diálogos, abas, teclado, console, requisições de rede, screenshot e snapshot com busca (browser_find).
  • Grupos opcionais, ativados com --caps:
    • network: mock de requisições e modo offline;
    • storage: cookies, localStorage, sessionStorage e estado salvo;
    • devtools: trace, vídeo, gravação de ações, destaque e anotação de elementos;
    • vision: cliques e mouse por coordenadas;
    • pdf: salvar a página em PDF;
    • testing: gerar locators e asserções de visibilidade e valor;
    • config: ler a configuração ativa.
  • Perfis de navegador: persistente (padrão, um por workspace), isolado em memória (--isolated) ou conectado ao seu Chrome/Edge pela extensão (--extension).
  • Chromium, Chrome, Edge, Firefox e WebKit. Emulação de dispositivo (--device, --mobile).
  • Gera código Playwright em TypeScript, Python, Java ou C# (--codegen).
  • Transporte HTTP (--port), imagem Docker oficial e uso programático (createConnection).
  • Funciona em VS Code, Cursor, Windsurf, Claude Desktop, Claude Code, Codex, Goose, Warp, Amp e outros clientes MCP.

Pré-requisitos

  • Node.js 18+.
  • Um cliente MCP.

Instalação

Configuração padrão (serve para a maioria dos clientes):

{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    }
  }
}

Por linha de comando:

claude mcp add playwright npx @playwright/mcp@latest          # Claude Code
codex mcp add playwright npx "@playwright/mcp@latest"         # Codex
code --add-mcp '{"name":"playwright","command":"npx","args":["@playwright/mcp@latest"]}'   # VS Code

Docker (só Chromium headless):

{
  "mcpServers": {
    "playwright": {
      "command": "docker",
      "args": ["run", "-i", "--rm", "--init", "--pull=always", "mcr.microsoft.com/playwright/mcp"]
    }
  }
}

Servidor separado com HTTP, útil quando o cliente roda sem tela:

npx @playwright/mcp@latest --port 8931

No cliente, use "url": "http://localhost:8931/mcp".

Comandos e uso

Peça ao agente em linguagem natural, por exemplo "abra localhost:3000, faça login com o usuário de teste e confira se o dashboard carrega". Ele chama as ferramentas browser_*.

Opções úteis (vão em "args", ou como variáveis PLAYWRIGHT_MCP_*):

Opção Para quê
--headless Roda sem janela (o padrão é com janela)
--browser <nome> chrome, firefox, webkit ou msedge
--caps <lista> Ativa grupos extras: network, storage, devtools, vision, pdf, testing, config
--isolated Perfil em memória, apagado ao fechar
--storage-state <arquivo> Carrega cookies e localStorage numa sessão isolada
--user-data-dir <pasta> Pasta do perfil persistente
--extension Conecta ao Chrome/Edge que você já usa
--device "iPhone 15" / --mobile Emula um celular
--viewport-size 1280x720 Tamanho da janela
--allowed-origins / --blocked-origins Filtra origens (não é barreira de segurança)
--redact-url-params access_token,code Esconde esses parâmetros de URL nas respostas
--secrets <arquivo .env> Arquivo de segredos no formato dotenv
--config <arquivo> Arquivo de configuração JSON

Também há --init-page (um arquivo TypeScript que prepara a página, por exemplo permissões e geolocalização) e --init-script (JavaScript injetado antes dos scripts da página).

Onde fica o perfil persistente:

Windows: %USERPROFILE%\AppData\Local\ms-playwright\mcp-{canal}-{hash-do-workspace}
macOS:   ~/Library/Caches/ms-playwright/mcp-{canal}-{hash-do-workspace}
Linux:   ~/.cache/ms-playwright/mcp-{canal}-{hash-do-workspace}

Um perfil persistente só aceita um navegador por vez. Para rodar vários clientes no mesmo projeto, use --isolated ou --user-data-dir diferentes.

Quando usar

  • Agentes autônomos que navegam, preenchem formulários e extraem dados por vários passos.
  • Testes exploratórios e testes que se corrigem sozinhos.
  • Clientes que só falam MCP, como Claude Desktop, Cursor e Windsurf.
  • Comparação: para agentes de código com terminal, o Playwright CLI é mais econômico. O Chrome DevTools MCP foca em depuração e desempenho no Chrome. O Playwright MCP é o mais completo para automação e funciona com vários navegadores.

Observações

  • Não é uma barreira de segurança. O próprio README avisa e manda seguir as boas práticas de segurança do MCP. Uma página maliciosa pode tentar manipular o agente com prompt injection.
  • browser_run_code_unsafe roda código JavaScript arbitrário no processo do servidor. A documentação diz que isso equivale a execução remota de código. Ative só em ambiente confiável.
  • Sessões logadas: o perfil persistente guarda logins em disco, e o modo --extension usa o seu navegador real com todas as contas. Prefira --isolated com --storage-state de uma conta de teste.
  • Exposição na rede: com --host 0.0.0.0, como no exemplo de Docker de longa duração, qualquer máquina que alcance a porta controla o navegador. Mantenha em localhost ou atrás de autenticação.
  • Acesso a arquivos: por padrão, fica limitado à pasta do projeto e URLs file:// são bloqueadas. --allow-unrestricted-file-access libera tudo.
  • Versões ainda 0.0.x (o último release é o v0.0.84, de out/2026), com mudanças frequentes. Fixar @latest atualiza sozinho a cada execução.
