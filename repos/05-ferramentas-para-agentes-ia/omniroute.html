O que é

O OmniRoute é um gateway de IA que roda na sua máquina (ou em um servidor) e expõe um único endpoint em http://localhost:20128/v1. Ferramentas de código como Claude Code, Codex, Cursor, OpenCode, Cline e Copilot apontam para esse endpoint, e o OmniRoute decide para qual provedor e modelo encaminhar cada requisição.

Você conecta suas próprias contas e chaves de provedores (o README cataloga 375 provedores, dos quais cerca de 150 com camada gratuita). Quando uma cota acaba ou um provedor falha, o roteador passa para a próxima opção. O modelo auto escolhe entre as conexões elegíveis, e é possível montar "combos" com estratégias de roteamento próprias.

Os tokens gratuitos citados no README (~1,62 bilhão por mês) são uma estimativa agregada de camadas gratuitas de terceiros, não uma concessão do OmniRoute. Cada provedor controla limites, disponibilidade e termos.

Principais recursos

  • Endpoint único compatível com OpenAI (chat, embeddings, imagens, áudio, OCR)
  • Fallback automático e agendamento ciente de cota entre provedores
  • Combos com 19 estratégias de roteamento e modelo auto sem configuração
  • Compressão de contexto (RTK + Caveman e outros motores) que, segundo o README, economiza de 15% a 95% dos tokens
  • Servidor MCP (stdio e HTTP, com 110 ferramentas) e servidor A2A para que agentes controlem o próprio gateway
  • CLI com mais de 80 comandos e modo remoto com tokens de acesso com escopo
  • Dashboard web, versão desktop/PWA e integração com o Copilot Chat do VS Code
  • Catálogo de camadas gratuitas com uso e cota restante em /dashboard/free-tiers

Pré-requisitos

  • Node.js e npm (o pacote é instalado globalmente via npm); alternativas: Docker, Bun, pnpm, código-fonte
  • Contas ou chaves de API dos provedores que você pretende usar
  • Com npm 11 ou superior, scripts de ciclo de vida podem ser bloqueados; o postinstall do OmniRoute é necessário (veja abaixo)
  • Para provedores via cookie web (como Gemini Web): o pacote inclui Playwright, mas não o binário do Chromium
  • Memória: a imagem Docker usa OMNIROUTE_MEMORY_MB=1024 por padrão; para um agente de código, o README recomenda heap de 8192 e container com pelo menos 10 GB

Instalação

Quick Start (seção aberta pelo usuário)

  1. Instalar e executar:
npm install -g omniroute
omniroute

O dashboard fica em http://localhost:20128 e a API em http://localhost:20128/v1.

Com npm 11 ou superior, permita os scripts dos pacotes citados no aviso do npm:

npm install -g --allow-scripts=omniroute,keytar,onnxruntime-node,@parcel/watcher,@swc/core,protobufjs,esbuild omniroute

Para reutilizar a lista de permissões nas próximas instalações globais:

npm config set allow-scripts=omniroute,keytar,onnxruntime-node,@parcel/watcher,@swc/core,protobufjs,esbuild --location=user
npm install -g omniroute

A lista pode mudar entre versões; use os nomes que o npm indicar no aviso. Avisos npm warn ERESOLVE são considerados inofensivos pelo README.

  1. Conectar um provedor com sua própria conta: Dashboard → Providers, escolha um provedor cujos termos e cota atendam seu uso e adicione a chave de API ou conclua o fluxo da conta.

  2. Apontar sua ferramenta de código:

Base URL: http://localhost:20128/v1
API Key:  [copiar de Dashboard → Endpoints]
Model:    auto            (ou provedor/modelo)
  1. Verificar:
curl http://localhost:20128/v1/models -H "Authorization: Bearer YOUR_KEY"

Docker

docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest

:latest segue a versão estável publicada mais recente. Para GitOps, fixe :X.Y.Z. As tags next e next-web são pré-lançamento e não são suportadas em produção.

Para um agente de código com mais memória:

docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest

Outras formas

# pnpm
pnpm add -g omniroute@latest --allow-build=better-sqlite3 --allow-build=@swc/core && omniroute

# Código-fonte
cp .env.example .env && npm install
PORT=20128 npm run dev

O README também documenta Bun, Nix, devbox, Podman e Arch Linux; consulte a seção "More install methods".

Comandos e uso

omniroute                # sobe gateway e dashboard (porta 20128)
omniroute chat           # cliente de chat em TUI (/model, /combo, /skill, /memory)
omniroute setup          # assistente guiado de primeira execução
omniroute doctor         # diagnostica provedores, portas e dependências nativas
omniroute --mcp          # servidor MCP via stdio (Claude Desktop, Cursor etc.)
omniroute connect <host> # conecta o CLI a uma instância remota
omniroute models         # lista modelos (da instância ativa)
omniroute configure codex  # escolhe um modelo e grava o perfil local do Codex

Teste rápido de chat:

curl http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'

Dar ao Claude Code as ferramentas do OmniRoute via MCP:

claude mcp add-server omniroute --type http --url http://localhost:20128/api/mcp/stream

Para clientes que não enviam cabeçalho Authorization, existem aliases com a chave na URL (/vscode/YOUR_KEY/...); o README recomenda usá-los só quando não houver alternativa.

Quando usar

  • Centralizar vários provedores de IA atrás de um único endpoint para suas ferramentas de código
  • Evitar interrupções por limite de cota com fallback automático
  • Reduzir o consumo de tokens com compressão de contexto
  • Dar a agentes (via MCP/A2A) controle sobre roteamento e configuração do gateway

Observações

  • Camadas gratuitas dependem de cada provedor (cadastro, aprovação, cartão de crédito), e os números do README são estimativas que sobem e descem.
  • O catálogo marca alguns provedores com tos: avoid (termos de uso arriscados); verifique os termos antes de conectar contas, especialmente provedores sem chave que podem rejeitar clientes de terceiros.
  • O gateway concentra suas chaves e o tráfego dos agentes: mantenha-o em 127.0.0.1 ou protegido por autenticação.
  • A branch padrão atual é release/v3.8.52; o projeto trabalha com canais de release e roadmap para o v3.9.0 LTS.
