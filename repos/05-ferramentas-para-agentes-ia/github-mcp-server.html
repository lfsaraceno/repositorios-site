GitHub MCP Server

Servidor MCP oficial do GitHub: deixa agentes de IA lerem repositórios e código, gerenciarem issues e PRs, acompanharem GitHub Actions, alertas de segurança e Dependabot, por linguagem natural, como servidor remoto hospedado ou local via Docker.

O que é

O servidor conecta ferramentas de IA (Claude Code, Claude Desktop, Codex, Cursor, VS Code com Copilot, Windsurf, Zed e outras) à plataforma GitHub. Com ele, o agente navega e pesquisa código, analisa commits, cria e atualiza issues e PRs, faz triagem de bugs, revisa mudanças, acompanha execuções de workflows, lê alertas de segurança e Dependabot e gerencia notificações e discussões.

Há duas formas de usar: o servidor remoto, hospedado pelo GitHub em https://api.githubcopilot.com/mcp/ (o jeito mais fácil, com OAuth ou token), e o servidor local, via Docker (ghcr.io/github/github-mcp-server) ou binário. As ferramentas são agrupadas em toolsets que você liga e desliga para reduzir o contexto.

Principais recursos

  • Toolsets: context, repos, issues, pull_requests, users (padrão), além de actions, code_security, dependabot, secret_protection, security_advisories, discussions, notifications, projects, gists, git, labels, orgs, governance, copilot e outros.
  • Seleção fina com --toolsets e --tools; all liga tudo.
  • Modo somente leitura (--read-only).
  • Modo lockdown: filtra conteúdo de autores sem permissão de push em repositórios públicos, para reduzir risco de prompt injection.
  • MCP Skills (opcionais, --features=skills): fluxos prontos como triagem de backlog, revisão de PR, preparação de release, triagem de falha de workflow e de alertas de segurança.
  • Modo insiders com recursos experimentais.
  • Suporte a GitHub Enterprise Server e Enterprise Cloud (ghe.com).

Pré-requisitos

  • Remoto: cliente MCP com suporte a servidor remoto (VS Code 1.101+, Claude Desktop, Cursor, Windsurf etc.).
  • Local: Docker em execução (ou o binário compilado).
  • Autenticação por OAuth ou por um Personal Access Token com as permissões mínimas necessárias.

Instalação

Claude Code (remoto, com token)

claude mcp add-json github '{"type":"http","url":"https://api.githubcopilot.com/mcp","headers":{"Authorization":"Bearer YOUR_GITHUB_PAT"}}'

No Windows, se o add-json der Invalid input, use o formato claude mcp add --transport http ... descrito no guia do Claude.

Claude Code (local, Docker)

claude mcp add github -e GITHUB_PERSONAL_ACCESS_TOKEN=YOUR_GITHUB_PAT -- docker run -i --rm -e GITHUB_PERSONAL_ACCESS_TOKEN ghcr.io/github/github-mcp-server

VS Code (remoto, OAuth)

{
  "servers": {
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/"
    }
  }
}

Guias para Copilot CLI, Codex, Cursor, OpenCode, Windsurf e Zed na pasta docs/installation-guides.

Comandos e uso

Configuração do servidor local:

github-mcp-server --toolsets repos,issues,pull_requests,actions,code_security   # só esses grupos
github-mcp-server --tools get_file_contents,issue_read,create_pull_request      # só essas ferramentas
GITHUB_TOOLSETS="default,stargazers" ./github-mcp-server                         # padrão + extra
./github-mcp-server --read-only                                                  # sem escrita
./github-mcp-server --lockdown-mode                                              # filtra conteúdo não confiável

No Docker, use as variáveis GITHUB_TOOLSETS, GITHUB_TOOLS, GITHUB_READ_ONLY=1 e GITHUB_LOCKDOWN_MODE=1.

Exemplos de pedido ao agente:

List the open issues labeled bug in this repo and suggest which to fix first.
Why did the last GitHub Actions run on main fail?

Quando usar

  • Triagem de issues, revisão de PRs e diagnóstico de falhas de CI pelo agente.
  • Acompanhar alertas do Dependabot e de varredura de código.
  • Agentes que trabalham em vários repositórios sem clonar.

Observações

  • Token com permissão mínima: dê só os escopos necessários, use tokens separados por projeto, rotacione e nunca commite (.env no .gitignore).
  • Prompt injection: issues e comentários de repositórios públicos podem conter instruções maliciosas; considere --lockdown-mode e --read-only. O lockdown é um filtro de melhor esforço, não um limite de autorização.
  • Ligar menos toolsets ajuda o modelo a escolher a ferramenta certa e economiza contexto.
  • A ficha não lista cada ferramenta individual (a lista completa está no README).
  • Alternativa sem MCP: a CLI gh, que o Claude Code já usa bem.
