RTK

Proxy de linha de comando em Rust que comprime a saída de comandos (testes, git, builds, logs) antes de o agente de IA ler, reduzindo até 90% dessa saída e o consumo de tokens, sem mudar o jeito de trabalhar.

O que é

Quando o agente roda git status ou npm test, ele lê dezenas ou centenas de linhas de saída que custam tokens. O RTK instala um hook no agente: o comando passa a rodar como rtk git status, e o agente lê um resumo de 3 linhas em vez de 40. Funciona em mais de 100 comandos, leva menos de 25 ms por comando e não exige configuração.

Três promessas: nunca bloqueia (se um filtro falhar, sai a saída original com o mesmo código de saída), nunca piora (não imprime mais que o comando original) e nada fica escondido (a saída cortada diz onde está a versão completa, e rtk bypass roda sem filtro).

Para ir além, pipelines comprimem também o que o agente lê fora do shell, mandam leituras grandes para um modelo mais barato e limpam o tráfego da API sem quebrar o cache de prompt.

Principais recursos

  • Filtros para Git, GitHub CLI, Cargo, npm/pnpm/vitest/jest/tsc, Python (pytest, ruff, mypy), Go, Ruby, .NET, Gradle/Maven, PHP, Docker, Kubernetes, AWS, Terraform e comandos de arquivo/busca.
  • Testes mostram só as falhas com a asserção; git diff com contexto reduzido; linters agrupados por regra.
  • rtk gain: painel de economia por dia, histórico e exportação JSON.
  • rtk discover: encontra economias perdidas.
  • Pipelines prontos e compartilhados pela comunidade.
  • RTK Proxy (opcional): comprime o tráfego para a API do provedor; rtk claude inicia tudo.
  • Suporte a 18 ferramentas: Claude Code, Copilot, Cursor, Gemini CLI, Codex, OpenCode, Windsurf, Cline, Antigravity e outras.
  • Telemetria anônima desligada por padrão.

Pré-requisitos

  • macOS, Linux, Windows ou WSL.

Instalação

brew install rtk                 # macOS e Linux com Homebrew
winget install rtk-ai.rtk        # Windows
curl -fsSL https://raw.githubusercontent.com/rtk-ai/rtk/refs/heads/master/install.sh | sh   # Linux, macOS ou WSL

Ligue ao agente e reinicie-o:

rtk init -g                      # Claude Code
rtk init -g --codex              # Codex (também --copilot, --gemini, --opencode, --agent cursor etc.)

Edição só Apache 2.0 (sem o motor de pipelines): brew install rtk-ai/tap/rtk-oss.

Comandos e uso

rtk gain                         # resumo da economia
rtk gain --graph                 # gráfico dos últimos 30 dias
rtk gain --daily                 # por dia
rtk discover                     # oportunidades de economia perdidas
rtk session                      # adoção do RTK nas sessões recentes
rtk bypass git log --oneline -20 # roda sem filtro
rtk pipeline add github:user/repo   # instala um pipeline compartilhado
rtk claude                       # inicia o proxy e abre o Claude por ele
rtk telemetry enable             # liga a telemetria (só com consentimento)

Quando usar

  • Reduzir custo e consumo de contexto em sessões longas do Claude Code.
  • Projetos com testes, builds e logs muito verbosos.
  • Medir quanto o agente gasta lendo saída de comandos.

Observações

  • Existe outro projeto chamado "rtk" no crates.io; confira que rtk gain mostra o painel.
  • 90% menos saída de comando não é 90% menos custo: a saída é só uma parte dos tokens de entrada. As contagens são estimadas (bytes / 4).
  • Licença: o CLI é Apache 2.0; o motor de pipelines e o RTK Proxy são BUSL-1.1 (uso em produção liberado; oferecer RTK ou derivado como produto ou serviço comercial a terceiros exige contato).
  • Pipelines podem reescrever comandos e mandar conteúdo para modelos; leia o arquivo antes de instalar.
  • RTK Pro (pago) é a camada para empresas: gateway, custos por time, mascaramento de segredos e auditoria.
  • Proposta complementar: Caveman (respostas curtas) e Headroom (compressão de saídas e arquivos).
