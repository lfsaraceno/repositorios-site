DSPy

Framework em Python de Stanford para programar modelos de linguagem em vez de escrever prompts à mão: você declara entradas e saídas, compõe módulos, e otimizadores como o GEPA reescrevem os prompts sozinhos a partir de uma métrica.

O que é

DSPy significa Declarative Self-improving Python. Em vez de prompts frágeis em texto, você escreve código Python composto de partes:

  • Signature: declara a tarefa como entradas e saídas, por exemplo "question -> answer". Os nomes dos campos já servem de dica ao modelo.
  • Módulo: define como resolver a tarefa. Por exemplo, Predict faz uma chamada simples, ChainOfThought raciocina antes de responder, ReAct usa ferramentas e ProgramOfThought e CodeAct geram código.
  • Adapter: transforma a signature em mensagens para o modelo e interpreta a resposta. O padrão é o XMLAdapter.
  • Métrica: uma função Python que dá nota à saída.
  • Otimizador: usa a métrica para melhorar o programa, ajustando instruções, exemplos (demos) ou até os pesos do modelo.

Cada etapa continua inspecionável, trocável e ajustável. A promessa do projeto é que um modelo pequeno e barato, otimizado, chegue perto de um modelo de ponta com prompt manual, ou até o supere. No tutorial oficial, o gpt-5.4-nano otimizado com GEPA passou de 78,1% para 90,1% na métrica, contra 82,4% do gpt-5.4 sem otimização.

Serve para classificadores simples, pipelines de RAG e loops de agentes. É um projeto acadêmico (Stanford NLP) com vários artigos publicados, entre eles o do GEPA (2025).

Principais recursos

  • Módulos prontos: Predict, ChainOfThought, ReAct, ProgramOfThought, CodeAct, Parallel, Retrieve e o RLM.
  • Ferramentas como funções Python comuns, além de suporte a MCP.
  • Otimizadores (também chamados de teleprompters):
Otimizador O que ajusta Quando usar
LabeledFewShot Exemplos Linha de base: não chama o modelo durante a compilação
BootstrapFewShot Exemplos Primeira tentativa segura: guarda as execuções que passaram na métrica
BootstrapRS / KNNFewShot Exemplos Busca entre conjuntos de exemplos / escolhe exemplos por similaridade em cada chamada
COPRO / MIPROv2 Instruções Quando o texto do prompt é o gargalo
GEPA Instruções Usa nota e feedback em texto da métrica, com um modelo de "reflexão" que reescreve o prompt
BootstrapFinetune Pesos Último recurso: exige um modelo que aceite fine-tuning
  • Avaliação em paralelo (dspy.evaluate.Evaluate) e juiz LLM escrito como signature.
  • Cache das chamadas ativo por padrão, histórico em dspy.inspect_history() e contexto por trecho com dspy.context.
  • Salvar e carregar o programa otimizado em JSON, para compilar uma vez e servir muitas vezes.
  • Provedores nativos: OpenAI, Anthropic, Google AI Studio, Azure OpenAI, Vertex AI, Ollama local e qualquer servidor compatível com a API da OpenAI.

Pré-requisitos

  • Python 3.10+.
  • Uma chave de API do provedor do modelo, ou o Ollama rodando localmente.

Instalação

pip install dspy
# ou, num ambiente virtual com uv
uv add dspy

Opcional: o motor de compatibilidade LiteLLM, para provedores ou recursos que o motor nativo não cobre:

pip install "dspy[litellm]"

Versão em desenvolvimento, direto do main:

pip install git+https://github.com/stanfordnlp/dspy.git

Comandos e uso

Configurar o modelo (a chave vai por variável de ambiente ou api_key=):

import dspy

dspy.configure(lm=dspy.LM("anthropic/claude-sonnet-4-5-20250929"))  # usa ANTHROPIC_API_KEY
# outros: "openai/gpt-5-nano", "gemini/gemini-2.5-pro", "ollama_chat/llama3.2:1b"

Primeiro programa:

haiku_generator = dspy.Predict("subject -> haiku")
result = haiku_generator(subject="computer science")
print(result.haiku)

dspy.inspect_history(n=1)   # mostra o prompt que o DSPy montou

Signature como classe:

class BasicQA(dspy.Signature):
    """Answer questions with short factoid answers."""
    question: str = dspy.InputField()
    answer: str = dspy.OutputField(desc="often between 1 and 5 words")

qa = dspy.ChainOfThought(BasicQA)
qa(question="What is the color of the sky?").answer

Otimizar com GEPA:

optimizer = dspy.GEPA(
    metric=minha_metrica,                  # devolve dspy.Prediction(score=..., feedback=...)
    reflection_lm=dspy.LM("openai/gpt-5.4"),
    auto="light",                          # "medium" e "heavy" testam mais candidatos
    num_threads=2,
)
otimizado = optimizer.compile(programa, trainset=train, valset=val)
otimizado.save("programa.json")

Recarregar:

novo = MeuPrograma()
novo.load("programa.json")

Para forçar uma resposta nova sem usar o cache, passe config={"rollout_id": 1, "temperature": 1.0} na chamada.

Quando usar

  • Pipelines com LLM que precisam de qualidade medida: classificação, extração, RAG, agentes com ferramentas.
  • Trocar de modelo, ou baratear com um modelo menor, sem reescrever prompts à mão: basta recompilar contra a mesma métrica.
  • Quando você tem exemplos rotulados, ou consegue escrever uma métrica, e quer melhorar os prompts de forma sistemática.
  • Não é um agente de código pronto nem um orquestrador de agentes como os da categoria Orquestração de agentes. É a biblioteca para construir o seu sistema com LLM.

Observações

  • Custo da otimização: a própria documentação avisa que o GEPA e o MIPROv2 podem gastar centenas de dólares em chamadas numa única compilação. Comece com LabeledFewShot ou BootstrapFewShot, use auto="light", compile uma vez e reaproveite o arquivo salvo.
  • Mudança recente no acesso a modelos: o DSPy agora usa motores nativos embutidos (lm15) e o LiteLLM virou um extra opcional. Isso quebrou opções de provedor, LMs personalizados, text completions e embeddings. Quem vem de versões antigas deve ler o guia de migração. O Vertex AI, por exemplo, mudou de vertex_ai/ para vertex:.
  • Segurança ao carregar programas:
    • Prefira salvar em .json.
    • Arquivos .pkl e o modo save_program=True usam cloudpickle e executam código ao carregar. Por isso exigem allow_pickle=True. Só carregue arquivos de origem confiável.
    • Ao carregar, api_base, base_url e model_list são descartados, a menos que você passe allow_unsafe_lm_state=True.
    • As chaves de API nunca são salvas no arquivo.
  • Overfitting: otimizar só os exemplos tende a se ajustar demais ao conjunto de treino, e otimizar instruções tende a generalizar melhor. Separe treino, validação e teste.
  • ProgramOfThought e CodeAct executam código gerado pelo modelo. Revise onde e como esse código roda.
  • Projeto ativo. O último release é o 3.4.1, de out/2026.
