PDFOxide (pdf_oxide)

Biblioteca de PDF em Rust, muito rápida, com bindings para Python, JavaScript/WASM, Go, C# e mais 15 linguagens. Extrai texto, imagens, tabelas e formulários, converte para Markdown e HTML, cria e edita PDFs. Também tem CLI e servidor MCP.

O que é

O PDFOxide é um kit de ferramentas para ler, criar e editar PDFs. O núcleo é escrito em Rust. As bindings das outras linguagens são camadas finas sobre esse mesmo núcleo, e a mesma correção chega a todas.

O autor criou o projeto para ter a velocidade do PyMuPDF sem a licença AGPL. Pelo benchmark do README, com 3.830 PDFs de suítes públicas (veraPDF, Mozilla pdf.js e SafeDocs), a média é de 0,8 ms por documento: cerca de 5× mais rápido que o PyMuPDF e 15× mais rápido que o pypdf. Esses números são do próprio autor.

O uso mais comum é transformar PDFs em Markdown limpo para pipelines de RAG e LLM. O RAGFlow, o AFFiNE e a pipeline de submissão do arXiv usam a biblioteca.

Principais recursos

  • Extração:
    • texto, com posição de cada caractere, palavra e linha;
    • imagens, tabelas, campos de formulário, anotações e marcadores;
    • extração só de uma região da página;
    • perfis prontos para tipos de documento (formulário, artigo acadêmico).
  • Conversão: página para Markdown (com detecção de títulos), HTML ou texto puro.
  • Criação e edição:
    • criar PDFs a partir de Markdown, HTML, texto ou imagens;
    • preencher formulários, anotar, rotacionar páginas, apagar áreas (whiteout) e fazer redação;
    • juntar, dividir e aplicar marca d'água;
    • criptografia AES-256 e PDFs protegidos por senha.
  • OCR de PDFs escaneados com modelos PaddleOCR (opcional, cerca de 12,5 MB de modelos).
  • Renderização de página para imagem nas builds nativas (opcional). Não existe na build WASM.
  • CLI pdf-oxide com 22 comandos e modo interativo (REPL).
  • Servidor MCP pdf-oxide-mcp, que dá ao Claude, ao Cursor e a outros clientes uma ferramenta extract. O processamento é local.

Pré-requisitos

Depende da linguagem:

  • Python 3.8–3.14: há wheels prontos para Linux, macOS e Windows.
  • Rust: cargo.
  • Navegador ou Node.js: o pacote npm pdf-oxide-wasm. Com Vite, use o vite-plugin-wasm.
  • CLI e MCP: Homebrew ou cargo.
  • OCR: ONNX Runtime e os modelos PaddleOCR, nas builds nativas.

Instalação

pip install pdf_oxide                    # Python
npm install pdf-oxide-wasm               # navegador / Node.js (WASM)
npm install pdf-oxide                    # Node.js nativo
brew install yfedoseev/tap/pdf-oxide     # CLI + servidor MCP
cargo install pdf_oxide_cli              # CLI via cargo

No Rust, adicione ao Cargo.toml:

[dependencies]
pdf_oxide = "0.3"

As outras linguagens (Go, C#, Java, Ruby, PHP, Swift, Kotlin, Dart e mais) têm comando próprio no README.

MCP no Claude Code / Claude Desktop / Cursor:

{
  "mcpServers": {
    "pdf-oxide": { "command": "crgx", "args": ["pdf_oxide_mcp@latest"] }
  }
}

Comandos e uso

Python:

from pdf_oxide import PdfDocument

with PdfDocument("relatorio.pdf") as doc:
    print(len(doc))                           # número de páginas
    for page in doc:
        texto  = page.text
        tabelas = page.tables
        md     = page.markdown(detect_headings=True)

Navegador (WASM), lendo o arquivo que o usuário escolheu:

import { WasmPdfDocument } from "pdf-oxide-wasm";

const bytes = new Uint8Array(await file.arrayBuffer());
const doc = new WasmPdfDocument(bytes);
try {
  for (let i = 0; i < doc.pageCount(); i++) {
    console.log(doc.extractText(i));
  }
} finally {
  doc.free();   // a memória do WASM precisa ser liberada à mão
}

CLI:

pdf-oxide text relatorio.pdf                    # extrai o texto
pdf-oxide markdown relatorio.pdf -o relatorio.md
pdf-oxide search relatorio.pdf "rede.?neural"   # busca com regex
pdf-oxide merge a.pdf b.pdf -o juntos.pdf
pdf-oxide forms w2.pdf --fill "name=Jane"       # preenche formulário

Use --pages 1-5 para escolher páginas e --json para saída em JSON.

Quando usar

  • Converter PDFs em Markdown para RAG, busca semântica ou contexto de LLM.
  • Extrair texto, tabelas e campos de formulário em lote, com velocidade.
  • Substituir o PyMuPDF quando a licença AGPL for um problema.
  • Num webapp, para extrair texto, buscar, preencher formulários ou editar o PDF no próprio navegador, sem enviar o arquivo a um servidor.
  • Não serve, sozinho, para exibir o PDF na tela. A build WASM não renderiza páginas. Para um visualizador, use o PDF.js ou o visualizador nativo do navegador, e o PDFOxide para texto, busca e edição.
  • Comparação no catálogo: o MarkItDown converte vários formatos (Word, Excel, PowerPoint, PDF) para Markdown, em Python. O PDFOxide é focado em PDF, roda em muitas linguagens e também cria e edita arquivos.

Observações

  • Licença: o código é MIT ou Apache-2.0, à sua escolha, e pode ser usado em projetos comerciais. Os nomes "PDFOxide" e "pdf_oxide" são marcas do autor: não dê esses nomes a um fork ou a um produto modificado (veja TRADEMARKS.md).
  • Limites da build WASM:
    • sem renderização de página;
    • sem assinaturas digitais;
    • OCR só numa build separada (wasm-ocr), experimental. Ela exige compilar com wasm-pack e baixar os modelos no navegador. Rode o OCR num Web Worker para não travar a interface.
  • PDFs de usuários são entrada não confiável. Num servidor, processe com limite de tamanho e de tempo. O projeto passa por fuzzing e afirma zero panics no corpus de teste, mas isso não substitui o limite.
  • Memória no WASM: cada WasmPdfDocument precisa de .free(), ou de using, para não vazar memória.
  • Projeto muito ativo, com releases frequentes (última: v0.3.78, set/2026). A API ainda está na série 0.x e pode mudar.
