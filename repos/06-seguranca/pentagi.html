O que é

O PentAGI (Penetration testing Artificial General Intelligence) é uma plataforma que roda na sua infraestrutura e faz testes de intrusão sozinha ou guiada por você. Você escreve em linguagem natural o alvo, o tipo de avaliação, o escopo e o resultado esperado. Um orquestrador divide o trabalho entre agentes especializados (pesquisador, desenvolvedor, executor, pentester e outros). Eles rodam as ferramentas dentro de contêineres isolados, guardam o que aprenderam e geram um relatório de vulnerabilidades com passos de reprodução.

É feito pela VXControl, empresa de engenharia de segurança de Dubai. Serve para engenheiros de segurança, pentesters, pesquisadores e red teams.

O que ele não é (segundo o próprio README): não é uma plataforma de simulação de ataques (BAS) ou de emulação de adversário com campanhas prontas, no estilo CALDERA.

Principais recursos

  • Dois modos de flow:
    • Automation: execução autônoma de ponta a ponta;
    • Assistant: conversa interativa para conduzir a investigação passo a passo, com a opção Use Agents para delegar subtarefas.
  • Mais de 20 ferramentas de pentest (nmap, Metasploit, sqlmap e outras), rodando em contêineres Docker isolados. A imagem padrão para pentest é vxcontrol/kali-linux, e o próprio LLM escolhe a imagem de cada tarefa.
  • Memória de longo prazo em PostgreSQL com pgvector. Grafo de conhecimento opcional com Graphiti e Neo4j, em beta, para relacionar hosts, serviços e achados.
  • Pesquisa na web:
    • navegador isolado (scraper);
    • buscadores: DuckDuckGo, Google Custom Search, Tavily, Firecrawl, Traversaal, Perplexity, SearXNG e Sploitus (busca de exploits e CVEs).
  • Mais de 10 provedores de LLM:
    • nuvem: OpenAI, Anthropic, Gemini, AWS Bedrock, DeepSeek, GLM, Kimi, Qwen, MiniMax, Mistral e xAI;
    • agregadores: OpenRouter e DeepInfra;
    • Azure OpenAI e qualquer endpoint compatível com OpenAI;
    • modelos locais com Ollama ou vLLM.
  • Supervisão de agentes:
    • limite de chamadas de ferramenta por agente;
    • um agente "reflector" que corrige quem trava;
    • opcional e em beta: monitor de execução e planejamento de tarefas, recomendados para modelos menores que 32B.
  • Relatórios na web, copiados ou baixados em Markdown ou PDF.
  • Arquivos por flow: envio de arquivos para o contêiner (/work/uploads/), biblioteca de recursos e cópia de arquivos do contêiner.
  • APIs REST e GraphQL com token Bearer, Swagger UI e GraphQL Playground.
  • Observabilidade opcional: Langfuse para traces de LLM e Grafana, VictoriaMetrics, Jaeger e Loki para o sistema.
  • Login opcional com GitHub e Google (OAuth). Vários usuários e várias instâncias com TENANT_ID.
  • A versão Enterprise (paga) acrescenta perfis de agente, plugins e servidores MCP, relatórios para clientes e visualização da cadeia de ataque em tempo real.

Pré-requisitos

  • Docker e Docker Compose, ou Podman.
  • Mínimo de 2 vCPU, 4 GB de RAM e 20 GB de disco livre.
  • Acesso à internet para baixar as imagens. Em redes restritas, configure um mirror de registry no daemon do Docker.
  • Pelo menos um provedor de LLM (chave de API) ou um servidor local (Ollama, vLLM). As chaves de busca são opcionais, mas melhoram os resultados.
  • Para rodar tudo local com qualidade, o guia oficial usa vLLM com Qwen3.5-27B-FP8 em 4× RTX 5090.

Instalação

Instalador interativo (recomendado)

Há um instalador com interface de terminal para Linux (amd64/arm64), Windows (amd64) e macOS (Intel e Apple Silicon). Ele verifica o sistema, cria o .env, configura provedores de LLM e buscadores, gera credenciais e certificados e sobe tudo com Docker Compose. Os links de download estão na seção Quick Start do README.

Exemplo para Linux amd64:

mkdir -p pentagi && cd pentagi
wget -O installer.zip https://pentagi.com/downloads/linux/amd64/installer-latest.zip
unzip installer.zip
sudo ./installer          # precisa de acesso ao socket do Docker

O instalador precisa falar com a API do Docker: rode como root ou coloque o usuário no grupo docker. Entrar no grupo docker equivale a ter acesso de root na máquina, então só faça isso para usuários de confiança.

Instalação manual com Docker Compose

mkdir pentagi && cd pentagi
curl -o .env https://raw.githubusercontent.com/vxcontrol/pentagi/master/.env.example

# arquivos de exemplo montados pelo compose (se faltarem, o Docker cria pastas no lugar)
curl -o example.custom.provider.yml https://raw.githubusercontent.com/vxcontrol/pentagi/master/examples/configs/custom-openai.provider.yml
curl -o example.ollama.provider.yml https://raw.githubusercontent.com/vxcontrol/pentagi/master/examples/configs/ollama-llama318b.provider.yml
curl -o example.bedrock.provider.yml https://raw.githubusercontent.com/vxcontrol/pentagi/master/examples/configs/bedrock.provider.yml

# edite o .env: chave de pelo menos um LLM e troque COOKIE_SIGNING_SALT e as senhas do banco

curl -O https://raw.githubusercontent.com/vxcontrol/pentagi/master/docker-compose.yml
docker compose up -d

A interface fica em https://localhost:8443. A conta inicial é admin@pentagi.com, com a senha padrão documentada no README. Troque a senha no primeiro login. Não existe cadastro público na tela de login.

Langfuse, Graphiti e observabilidade têm compose próprios (docker-compose-langfuse.yml, docker-compose-graphiti.yml, docker-compose-observability.yml). Rode o docker-compose.yml principal primeiro, porque ele cria as redes que os outros usam.

Produção

Para produção, o README recomenda dois nós: os contêineres de trabalho rodam num servidor separado, com Docker-in-Docker e TLS. Veja o guia do worker node.

Comandos e uso

Primeiro flow: abra Flows, clique em New Flow, escolha Automation ou Assistant, selecione o provedor de LLM e descreva o alvo. Exemplo do README:

Assess https://target.example for common web application vulnerabilities. Focus on authentication, file handling, and injection issues. Stay within the provided target only and summarize confirmed findings with reproduction steps.

Um bom prompt diz o alvo, o tipo de avaliação, os limites de escopo (regras de engajamento) e o resultado esperado. Há um prompt-base para pentest web em examples/prompts/base_web_pentest.md. Comece com um alvo pequeno e um objetivo só.

API (gere o token em Settings da interface):

# listar flows pela API REST
curl https://your-pentagi-instance:8443/api/v1/flows \
  -H "Authorization: Bearer YOUR_API_TOKEN"

Utilitários de diagnóstico dentro do contêiner:

docker exec -it pentagi /opt/pentagi/bin/ctester -verbose            # testa os modelos configurados para cada agente
docker exec -it pentagi /opt/pentagi/bin/ctester -type anthropic     # testa um provedor específico
docker exec -it pentagi /opt/pentagi/bin/etester test -verbose       # testa o provedor de embeddings e o banco
docker exec -it pentagi /opt/pentagi/bin/ftester -flow 123 describe  # mostra tarefas e subtarefas de um flow travado
docker logs pentagi                                                  # primeiro lugar para olhar quando um flow trava

Flow parado sem progresso costuma ser provedor de embeddings mal configurado. Teste com etester. Erro failed to select primary docker image via llm call indica problema no LLM do agente simple, não no Docker.

Quando usar

  • Pentest autorizado de aplicações web e redes, com um time de agentes rodando ferramentas reais e gerando relatório.
  • Laboratórios, CTFs e ambientes de treino seus.
  • Ambientes isolados (air-gapped), com modelo local via vLLM ou Ollama.
  • Integrar testes de segurança em automações via API REST ou GraphQL.
  • Comparação no catálogo:
    • o RAPTOR é um framework de pesquisa de segurança sobre o Claude Code, com análise estática, de binários e patches;
    • a Security Audit Skill e as Trail of Bits Skills auditam código-fonte dentro do agente de código;
    • o PentAGI ataca sistemas em execução a partir de uma plataforma própria, com interface web.

Observações

  • Uso legal e autorizado apenas. O EULA vale para as imagens Docker e a interface, além da licença MIT. Ele exige permissão explícita do dono da rede e proíbe uso em infraestrutura crítica sem validação. Também deixa com você a responsabilidade por tudo o que os agentes fizerem. Testar sistemas de terceiros sem autorização é crime no Brasil (Lei 12.737/2012, art. 154-A do Código Penal).
  • Agente autônomo com ferramentas ofensivas. Os agentes executam comandos e exploits de verdade. Defina o escopo com clareza, acompanhe a execução e use o Assistant para frear ou redirecionar o flow.
  • Superfície de risco da instalação:
    • o serviço pentagi roda como root no compose padrão para acessar o docker.sock;
    • montar o socket do Docker do host (DOCKER_SOCKET) dá ao agente controle total da máquina. O README recomenda isso só em desenvolvimento, num nó só;
    • cada flow publica duas portas TCP (faixa 28000–29999) em todas as interfaces do host, para conexões de retorno como reverse shells. O Docker passa por cima das regras do ufw, então bloqueie essa faixa num firewall à frente do host ou na chain DOCKER-USER;
    • a API do Graphiti não tem autenticação. O compose a liga só em 127.0.0.1.
  • Dados sensíveis:
    • prompts, saídas de ferramentas, credenciais encontradas e evidências vão para o provedor de LLM e para os buscadores que você configurar. Avalie a LGPD e os contratos com o cliente antes;
    • logs, banco, Neo4j e backups guardam esse material;
    • apagar um flow não apaga a pasta flow-{id}-data/ do disco.
  • Provedores de LLM:
    • alguns modelos acionam as proteções de cibersegurança do provedor. O README cita os GPT-5, 5.1 e 5.2 da OpenAI, que pedem acesso verificado;
    • no AWS Bedrock, as cotas padrão para Claude são muito baixas.
  • Custo: o monitor de execução e o planejamento multiplicam por 2 a 3 o tempo e os tokens. O Graphiti gera custos próprios de LLM e de embeddings.
  • Embeddings: não troque de provedor depois de indexar dados. Se trocar, rode etester flush ou reindex.
  • Os serviços VXControl Cloud (inteligência de ameaças, suporte de IA, recursos premium) exigem chave de licença e termos próprios. A versão Enterprise é paga.
  • Projeto ativo, com último release v2.2.0 (out/2026).
