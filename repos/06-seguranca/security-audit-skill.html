O que é

É a skill que serviu de semente para o harness de descoberta de vulnerabilidades da Cloudflare, descrito no post "Build your own vulnerability harness". O harness original cresceu para um sistema multi-estágio; esta skill é o ponto de partida para um único repositório.

Ela transforma o agente de código em um auditor de segurança, orquestrando agentes isolados por reconhecimento, caça guiada por cobertura, validação de candidatos, saída estruturada, verificação independente dos registros e relatório neutro quanto ao alvo.

Principais recursos

  • Auditoria em seis fases: reconhecimento, caça guiada por cobertura, validação de candidatos, saída estruturada, verificação independente e relatório
  • Veredictos distintos: confirmed (rastro completo da fonte e resultado observado), needs_validation (fato pendente exato, sem severidade) e rejected
  • Validação adversarial: o agente que verifica um achado nunca é o que o encontrou
  • Arquivos findings.json e coverage-ledger.json validados por schema e por validadores sem dependências (Node.js)
  • Relatórios derivados: REPORT.md, FINDINGS-DETAIL.md e NEEDS-VALIDATION.md
  • Classes de caça por tipo de alvo: memória/binário, IA e LLM, web/protocolos/autenticação, client-side, cadeia de suprimentos, nuvem, RPC/mensageria, exaustão de recursos, isolamento de dados e desktop/mobile
  • Execuções repetidas são aditivas: usam ledgers anteriores para atacar lacunas

Pré-requisitos

  • Agente de código com modelo que suporte uso de ferramentas e subagentes paralelos
  • Node.js para os validadores de achados e do ledger de cobertura
  • Sandbox aplicado pelo sistema operacional para builds, testes, processos, navegadores, fuzzers e fixtures controlados pelo alvo: sem rede externa, ambiente saneado com lista de permissão, limites de recursos e escrita apenas em caminhos de rascunho atribuídos

Instalação

Com o Skills CLI:

npx skills add https://github.com/cloudflare/security-audit-skill \
  --skill security-audit

Instalação em nível de usuário:

npx skills add https://github.com/cloudflare/security-audit-skill \
  --skill security-audit \
  --global

Rode npx skills --help para opções de seleção de agente e modo não interativo.

Comandos e uso

Inicie o agente dentro (ou apontando para) do código que será auditado e peça:

security audit this codebase
find security vulnerabilities in ./src
do a security review, output to ~/audits/my-project

A skill é ativada quando o pedido corresponde ao gatilho (auditoria de segurança, achar vulnerabilidades, pen-test do código). Um pedido direto de auditoria usa o modo completo; perguntas de segurança e trabalhos focados usam o modo de orientação, a menos que você peça artefatos de relatório.

Quando usar

  • Auditoria de segurança de um repositório próprio antes de release
  • Triagem de candidatos a vulnerabilidade com validação independente para reduzir falsos positivos
  • Gerar relatórios de auditoria estruturados e rastreáveis
  • Reauditar um projeto ao longo do tempo, aproveitando a cobertura anterior

Observações

  • Use apenas em código que você possui ou tem autorização para auditar.
  • Rode builds e testes do alvo somente em sandbox com rede desativada, como exigido pelo README.
  • Princípios do projeto: só confirmar falhas de fronteira estabelecidas, lacunas de defesa em profundidade são notas de hardening (não vulnerabilidades) e múltiplas execuções melhoram a cobertura (nos testes dos autores, uma execução achou cerca de metade do total encontrado por execuções repetidas).
  • Auditorias com vários agentes consomem muitos tokens.
