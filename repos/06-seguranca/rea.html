O que é

REA é um MCP único para engenharia reversa. Você pede ao agente que investigue um recurso de um aplicativo; o REA inspeciona o alvo sem precisar do código-fonte, devolve as conclusões com as evidências e limitações, e o agente usa isso para explicar o comportamento ou escrever e testar uma implementação própria.

A análise roda localmente. Para binários nativos, o REA usa um motor já instalado (Hopper, Ghidra ou IDA); a análise estática de JavaScript não precisa de motor nativo. Os mesmos fluxos podem ser usados pelo terminal.

O README alerta para obter o REA apenas de fontes oficiais (repositório morluto/rea, rea.tools ou o pacote npm rea-agents), pois nomes parecidos não garantem um download legítimo.

Principais recursos

  • Servidor MCP com catálogo gerado de ferramentas e prompts guiados de investigação
  • Binários nativos: pseudocódigo, assembly, strings, símbolos, chamadas e referências (Hopper, Ghidra ou IDA)
  • JavaScript/Electron: módulos, imports, source maps, rotas, IPC e add-ons nativos
  • Assemblies .NET, APKs Android (via JADX), apps Flutter, firmware (Binwalk/Unblob) e bancos SQLite
  • Websites, capturas de rede (HAR, SAZ) e capturas de pacotes (TShark)
  • Resultados acompanhados das evidências e das limitações de cada conclusão
  • Setup automatizado para Claude Code, Codex, Cursor, Gemini CLI, Grok Build e outros agentes

Pré-requisitos

  • Node.js 22.x (>=22.19), 24.x (>=24.11) ou 26+, com npm
  • Motor de análise nativa conforme o alvo: Hopper, Ghidra ou IDA (o setup pode instalar o Hopper com sua aprovação)
  • Para APKs: JADX headless e um JDK completo; para sites: um navegador da família Chrome
  • No Linux: um ps compatível com procps no PATH (necessário para Ghidra, JADX, ferramentas de firmware e análise estática de JavaScript/Electron)
  • Outras ferramentas dependem do alvo (pwntools, WABT, TShark, adb etc.), conforme a tabela do README

Instalação

Configurar o agente

npx rea-agents setup

Escolha os agentes, revise as mudanças propostas e aprove. O setup registra o servidor MCP e instruções de fluxo de trabalho, com backup da configuração existente. Reinicie o agente depois.

CLI global (opcional)

npm install --global rea-agents
rea --help

Atualizar

rea update
# ou, se usa npx:
npx rea-agents@latest setup

Com Bun, use bunx rea-agents@latest no lugar de npx rea-agents@latest.

Comandos e uso

Prompt para o agente:

Understand how search works in the Notes app, show me the evidence, and build a
similar feature for my project.

Análise estática de um app JavaScript/Electron (diretório extraído ou ASAR) pelo terminal:

npx -y rea-agents@latest analyze-javascript-application /caminho/absoluto/do/app --json

O resultado inclui módulos, imports, fronteiras do Electron e evidências. Para análise nativa, configure antes um provedor; veja o guia de CLI e Evidence do repositório (docs/cli.md).

Quando usar

  • Entender como um recurso de um app funciona quando você não tem o código-fonte, para fins de interoperabilidade ou aprendizado
  • Analisar software próprio ou autorizado: auditoria de binários, APKs e apps Electron
  • Preservação e estudo de software, e pesquisa em segurança defensiva
  • Documentar comportamento de sistemas legados

Observações

  • Uso responsável: o projeto destina-se a pesquisa lícita, educação, interoperabilidade, preservação de software e análise de software que você possui ou está autorizado a examinar. Veja o DISCLAIMER.md do repositório.
  • A análise estática de JavaScript e .NET lê os arquivos sem executá-los; a captura em tempo de execução executa ou interage com o alvo com as permissões do seu usuário, então analise amostras desconhecidas em ambiente isolado.
  • O REA muda rápido; mantenha-o atualizado.
  • Alguns recursos dependem de ferramentas de terceiros com termos próprios (Hopper, IDA etc.); o REA não instala nem atualiza provedores como GNU objdump e Rizin.
  • Vulnerabilidades do próprio REA devem ser reportadas via SECURITY.md.
