MillionSend

Plataforma open source de envio de e-mails, compatível com a API do Resend: transacional, em massa (broadcasts), contatos, templates, webhooks e SMTP, enviando pela sua própria conta AWS SES (self-hosted com Docker) ou pela nuvem deles.

O que é

O MillionSend é uma alternativa open source ao Resend. Você roda o painel e a API no seu servidor, e os e-mails saem pela sua conta do Amazon SES, que cobra por envio e é bem mais barato que serviços de e-mail em volume. Também existe uma versão hospedada (cloud).

A API tem os mesmos formatos de requisição e resposta do Resend. Segundo o README, migrar de um para o outro é trocar duas variáveis de ambiente, sem reescrever a integração. Uma CLI copia contatos, segmentos, tópicos, templates, webhooks, domínios e supressões do Resend.

O self-host roda em dois contêineres: Postgres e um contêiner do app com a API (porta 3001), o worker e o painel web (porta 3000). O painel tem versão em português do Brasil, e o projeto é mantido principalmente por desenvolvedores brasileiros.

Principais recursos

  • API de e-mails compatível com Resend: enviar, enviar em lote, consultar e cancelar, com header Idempotency-Key para não duplicar reenvios.
  • Broadcasts: compor, agendar e enviar para todos os contatos, um segmento ou um tópico; dá para cancelar enquanto está agendado.
  • Contatos: status de inscrição, segmentos, tópicos, importação de CSV e criação em lote.
  • Templates reutilizáveis com campos de mesclagem por contato.
  • Descadastro em um clique (RFC 8058), com cabeçalho List-Unsubscribe e página de descadastro hospedada.
  • Lista de supressão: hard bounces e reclamações são bloqueados automaticamente.
  • Métricas: envios por dia, com taxa de bounce e de reclamação comparadas aos limites do SES.
  • Webhooks assinados (padrão Standard Webhooks), com log de entregas.
  • Domínios: verificação de DNS guiada, com DKIM próprio ou gerenciado pelo SES.
  • Relay SMTP na porta 2587, autenticado com chave de API.
  • Recebimento de e-mail (beta): MX próprio, API de recebimento do Resend e webhook email.received.
  • Logs de requisições da API, com segredos ocultados.
  • Monitoramento de conteúdo (opcional): um modelo da TypeSafe avalia os envios. Desligado por padrão no self-host.
  • SDKs em MIT para Node, Python, PHP e Go (pacote millionsend).

Pré-requisitos

  • Docker com Compose.
  • Node 18+ para o assistente de instalação.
  • Conta AWS com acesso ao SES na região escolhida.
  • Um domínio próprio para envio.

Instalação

Assistente (sem clonar)

Numa pasta vazia:

mkdir millionsend && cd millionsend
npx @millionsend/setup              # --dry-run mostra o plano sem alterar nada

O assistente cria o .env com segredos gerados e, se você quiser, provisiona na AWS o usuário IAM, o tópico SNS de eventos, o configuration set do SES e os buckets S3 de uploads e backups. Depois sobe a imagem pronta com docker compose up -d. Cada etapa pode ser pulada e o assistente pode ser rodado de novo sem problema.

Painel em http://localhost:3000 e API em http://localhost:3001.

Manual

mkdir millionsend && cd millionsend
curl -O https://raw.githubusercontent.com/MillionSend/millionsend/main/deploy/docker-compose.yml
curl -o .env https://raw.githubusercontent.com/MillionSend/millionsend/main/.env.example
# preencha o .env (abaixo) e então:
docker compose up -d

No .env:

  • MASTER_ENCRYPTION_KEY e BETTER_AUTH_SECRET: gere cada um com openssl rand -base64 32.
  • APP_BASE_URL: a URL em que você abre o painel. Se não bater, o login falha com "invalid origin".
  • AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY: as credenciais da AWS.
  • COMPOSE_PROFILES (opcional): docs, smtp, mx (receber e-mail), clamav (antivírus) e backup.

As migrações do banco rodam sozinhas ao iniciar. Build a partir do código, deploy com nginx, backups e múltiplas regiões do SES estão no SELF_HOSTING.md.

Atualizar

docker compose pull && docker compose run --rm --no-deps millionsend migrate && docker compose up -d

Comandos e uso

npx @millionsend/setup                            # instala ou abre o menu de próximos passos
npx @millionsend/cli migrate --from resend        # copia dados do Resend (só lê do Resend; pode repetir antes da troca)

No dia a dia, você usa o painel (domínios, chaves ms_, contatos, broadcasts, templates, métricas). Também pode chamar a API pelos SDKs ou pelo SDK do Resend apontado para a sua instância.

Quando usar

  • Você já usa Resend e quer pagar só o custo do SES.
  • Precisa de e-mail transacional e newsletters/broadcasts no mesmo lugar, no seu servidor.
  • Quer painel em português e dados de contatos sob seu controle (LGPD).

Observações

  • Licença AGPL-3.0: se você modificar o código e oferecer como serviço pela rede, precisa disponibilizar o código modificado. Os SDKs são MIT. O nome e a marca MillionSend não são cobertos pela AGPL.
  • Sandbox do SES: contas novas da AWS só enviam para destinatários verificados. Para enviar a qualquer pessoa, peça acesso de produção à AWS.
  • Segredos: o .env guarda todas as chaves da instância. Proteja o arquivo (chmod 600 no Linux) e deixe-o fora do git e dos backups.
  • E-mail em massa e LGPD: envie só para contatos com consentimento e mantenha o descadastro funcionando. Taxas altas de bounce ou reclamação podem fazer a AWS suspender o SES.
  • Projeto novo: criado em ago/2026, com poucas estrelas, um mantenedor principal e versões quase diárias (v0.30.x em nov/2026).
  • Li o README inteiro, mas só o início do SELF_HOSTING.md (1.900 linhas). Proxy reverso, backups, recebimento de e-mail e regiões ficaram de fora desta ficha.
  • Relacionado no catálogo: o Mailflare é uma caixa de e-mail completa (substitui o Google Workspace). O MillionSend é para enviar e-mails a partir de um sistema ou campanha.
