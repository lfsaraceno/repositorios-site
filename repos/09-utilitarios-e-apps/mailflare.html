O que é

O Mailflare é uma suíte de colaboração que você hospeda: caixas de e-mail com domínio próprio (pessoais ou compartilhadas), regras de roteamento, agenda com convites, página pública de agendamento (estilo Calendly), Drive para arquivos e um assistente de IA que busca e-mails, rascunha respostas e gerencia eventos.

Roda de duas formas com o mesmo código: no Cloudflare Workers (D1, R2 e filas da Cloudflare, com botão "Deploy to Cloudflare") ou em um único contêiner Docker em qualquer servidor, com SQLite e arquivos locais em volume. Envio e recebimento podem usar Cloudflare Email, Resend, Amazon SES ou qualquer relay SMTP.

O recebimento pode sair de graça (Cloudflare Email Routing) e o envio também, pelo plano gratuito do Resend (3.000 e-mails/mês) ou do SES. A interface está em 34 idiomas, incluindo português do Brasil.

Principais recursos

  • E-mail com domínio próprio, caixas pessoais ou compartilhadas, controle de acesso e aliases.
  • Regras de roteamento: guardar, encaminhar, rejeitar ou classificar e-mails recebidos.
  • Agenda com eventos recorrentes, fusos horários e convites por e-mail; Booking com link público para marcar horários livres.
  • Drive para guardar e compartilhar arquivos (R2, Backblaze B2 ou AWS S3).
  • Assistente de IA (Cloudflare Workers AI ou provedor compatível com OpenAI) e servidor MCP em /mcp para conectar clientes externos como Claude Code.
  • Bancos: Cloudflare D1 (padrão), PostgreSQL, MySQL, Turso/libSQL ou SQLite local; funciona com Supabase, Neon, PlanetScale e TiDB via DATABASE_URL.
  • Admin: usuários, chaves de API, webhooks, logs de auditoria e backups diários.
  • Importação de IMAP, Gmail Takeout, arquivos .eml e .mbox; PWA com notificações push.

Pré-requisitos

  • Cloudflare: conta Cloudflare com o domínio como zona e um token de API (CF_TOKEN) com as permissões listadas abaixo. O envio pela própria Cloudflare exige o plano Workers Paid (US$ 5/mês); com Resend ou SES não.
  • Docker: servidor com Docker e porta 25 liberada para receber e-mail pelo listener SMTP embutido (várias nuvens bloqueiam a 25; Hetzner e a maioria das VPS não).
  • Desenvolvimento local: Node.js e npm.

Instalação

Cloudflare (botão)

  1. Clique em Deploy to Cloudflare no README. Mantenha o nome do app como mailflare, senão quebra.
  2. Abra o app em /setup e crie a conta de administrador.
  3. Adicione um domínio da mesma conta Cloudflare e crie a primeira caixa.

O CF_TOKEN é obrigatório. Crie um token com escopo:

  • All accounts: Email Sending:Edit, DNS Settings:Edit, Email Routing Addresses:Edit
  • All zones: DNS Settings:Edit, Email Routing Rules:Edit, Zone Settings:Edit, DNS:Edit

Cloudflare com agente de IA

O README traz um prompt para colar no Claude Code, Codex ou Cursor. O agente lê a documentação, pede o account ID e dois tokens (deploy e CF_TOKEN) por entrada secreta, cria o D1 mailflare, o bucket R2 mailflare-raw e as filas mailflare-inbound, mailflare-outbound e mailflare-agent, roda npm run deploy e define o CF_TOKEN como secret. As migrações remotas ficam por conta da página /setup.

Docker (self-hosted)

git clone https://github.com/hieunc229/mailflare && cd mailflare
cp .env.docker.example .env.docker      # configure como receber e enviar e-mail
docker compose up -d --build

Abra http://seu-host:3000/setup, crie o admin e adicione o domínio. Todos os dados ficam no volume mailflare-data (/data no contêiner). Atrás de proxy reverso, defina APP_URL=https://mail.example.com e encaminhe o WebSocket de /api/realtime.

Sem Docker (Node)

npm ci
npm run build:node
MAILFLARE_RUNTIME=node NODE_ENV=production DATA_DIR=./data node dist/server.mjs

A porta 25 exige root ou capability; senão use SMTP_INBOUND_PORT=2525 com redirecionamento de porta.

Comandos e uso

Desenvolvimento local

cp .dev.vars.example .dev.vars   # adicione as credenciais Cloudflare aqui
npm install
npm run db:migrate:local         # aplica as migrações no banco local
npm run dev                      # abre em http://localhost:3000
npm run db:seed                  # carrega dados de exemplo
npm run build                    # build do Worker
npm run deploy                   # build e deploy
npm run lint                     # lint e checagem de tipos
npm run push:keys                # gera par de chaves VAPID para notificações push

Operação no Docker

docker compose logs -f mailflare   # logs

Para atualizar, puxe a nova imagem e recrie o contêiner; as migrações rodam na inicialização. O botão de atualização do app fica desativado no self-hosted.

Variáveis principais (Docker)

  • SMTP_URL=smtps://user:pass@host:465: relay de saída (SES, Postmark, Mailgun, Postfix etc.).
  • MAIL_HOSTNAME: host para onde aponta o MX.
  • DATABASE_URL: troca o SQLite por PostgreSQL, MySQL ou libSQL.
  • AI_BASE_URL, AI_API_KEY, AI_MODEL: provedor do assistente (padrão gpt-4o-mini).
  • RESEND_API_KEY ou AWS_ACCESS_KEY_ID/AWS_SECRET_ACCESS_KEY/AWS_REGION: envio por Resend ou SES.

MCP (conectar Claude Code e outros clientes)

  1. Em Settings → API keys, crie uma chave com Allow MCP access e escolha as caixas e ferramentas permitidas (a chave aparece uma vez só).
  2. Conecte o cliente a https://<sua-origem-mailflare>/mcp (Streamable HTTP) com o cabeçalho Authorization: Bearer <key>.

Ferramentas incluem list_emails, update_draft, request_send e, com permissão de agenda, get_schedule, find_free_time, create_event etc. O request_send só cria um pedido de revisão: o envio precisa ser confirmado por uma pessoa logada no Mailflare. Para gerenciar domínios e contas, use uma chave separada em Admin → API keys (ela não dá acesso ao conteúdo dos e-mails).

Quando usar

  • Ter e-mail com domínio próprio, agenda e drive sem pagar Google Workspace por usuário.
  • Montar caixas compartilhadas (contato@, suporte@) com controle de acesso para uma equipe pequena.
  • Dar a um agente de IA acesso controlado a e-mail e agenda via MCP, com revisão humana antes de enviar.
  • Migrar e-mails antigos via IMAP, Gmail Takeout ou .mbox.

Observações

  • Licença AGPL-3.0: se você modificar e oferecer o Mailflare como serviço para terceiros, precisa disponibilizar o código-fonte das modificações.
  • Hospedar e-mail próprio exige cuidar de entregabilidade (SPF, DKIM, DMARC; o app mostra os registros) e da segurança do servidor.
  • Contas novas do Amazon SES começam em sandbox; é preciso pedir acesso de produção à AWS.
  • O CF_TOKEN tem permissões amplas de DNS em todas as zonas; guarde-o como secret e nunca o coloque em commits.
  • No Docker, a fila de jobs fica em memória; o e-mail recebido é gravado no volume antes, então reiniciar não perde mensagens.
