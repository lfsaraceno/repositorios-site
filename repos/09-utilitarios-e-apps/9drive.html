O que é

O 9Drive conecta várias contas do Google Drive em um painel de armazenamento virtual. Os usuários se registram (e-mail e senha ou Google), conectam contas de Drive, acompanham a cota, enviam arquivos, organizam em pastas virtuais e visualizam arquivos. O backend decide para qual conta enviar cada upload, escolhendo uma com espaço livre suficiente.

Também aceita storages compatíveis com S3 (MinIO, Cloudflare R2, Wasabi, Backblaze B2, AWS S3). Os uploads passam em stream pelo backend: os arquivos não ficam gravados no servidor.

Principais recursos

  • Várias contas do Google Drive e storages S3 em um só painel.
  • Upload direto em stream, sem guardar arquivos no servidor; no Drive, tudo vai para uma pasta raiz 9drive.
  • Políticas de roteamento: mais espaço disponível, round-robin e ordem de prioridade.
  • API externa de upload com chaves de API (POST /api/v1/uploads), com chave exibida uma vez, armazenada com hash e revogável.
  • Login por e-mail e senha ou Google, com conexão automática do primeiro Drive.
  • Painel de cota, sincronização manual da pasta 9drive para o MySQL, pastas virtuais, preview, download, renomear, mover e excluir.
  • Atualização do sistema via update.sh pelas Configurações (setup com PM2) e reCAPTCHA opcional.

Pré-requisitos

  • Node.js 20+ e npm.
  • MySQL 8+ (o setup com Docker já inclui MySQL).
  • Projeto no Google Cloud com a Google Drive API ativada e um OAuth Client ID/Secret.

Instalação

Setup automático (recomendado)

Windows (PowerShell), dentro da pasta do projeto:

powershell -ExecutionPolicy Bypass -File .\setup.ps1

Linux/macOS:

bash ./setup.sh

O script gera os arquivos .env com chaves seguras, instala dependências e gera o cliente Prisma. Informe a URL de conexão do MySQL quando pedida (Client ID/Secret do Google podem ficar para depois). Depois aplique as migrations e inicie em dois terminais:

cd backend
npm run prisma:migrate
npm run dev

cd frontend
npm run dev

O frontend sobe em http://localhost:5173 e o backend em http://localhost:4000.

Configuração do Google

No Google Cloud Console: ative a Google Drive API, configure a tela de consentimento OAuth (tipo Externo, escopos do Drive e de perfil/e-mail, e adicione usuários de teste), crie um OAuth Client do tipo "Web application" com origem http://localhost:5173 e redirect http://localhost:4000/connected-accounts/google/callback. Coloque GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET e GOOGLE_REDIRECT_URI no backend/.env e rode:

cd backend
npm run seed:google-config

Docker

cp .env.docker.example .env      # no PowerShell: Copy-Item .env.docker.example .env
# edite o .env (senhas, JWT_ACCESS_SECRET, TOKEN_ENCRYPTION_KEY, credenciais do Google)
docker compose up -d --build

Serviços: frontend em http://localhost:5173, backend em http://localhost:4000 e MySQL.

Comandos e uso

docker compose logs -f backend                         # logs do backend
docker compose exec backend npm run seed:google-config # atualiza a config OAuth do Google
docker compose down                                    # para os containers

No painel: conecte contas em Configurações (Connect Drive), escolha a política de roteamento, gere chaves de API e use a documentação de API embutida (com exemplos cURL e JavaScript).

Quando usar

  • Somar o espaço gratuito de várias contas do Google Drive em um único destino de upload.
  • Oferecer uma API de upload que distribui arquivos entre Drive e S3.

Observações

  • A tela de consentimento exige escopo completo do Drive (auth/drive) para sincronizar arquivos da pasta 9drive; avalie as implicações de segurança.
  • Use JWT_ACCESS_SECRET e TOKEN_ENCRYPTION_KEY longos e aleatórios, e nunca versione o .env.
  • Em modo "Testing", o Google exige cadastrar os usuários de teste, ou mostrará "Error 403: access_denied".
  • Usar várias contas gratuitas para ampliar o espaço pode conflitar com os termos de uso do Google; leia-os antes.
