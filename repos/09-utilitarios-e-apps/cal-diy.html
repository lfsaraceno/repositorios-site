O que é

O Cal.diy é um fork do Cal.com com todo o código empresarial e comercial removido. Você publica seus horários disponíveis e as pessoas marcam reuniões num link, com integração a calendários e videochamada (Daily.co).

Diferenças em relação ao Cal.com: não tem Times, Organizações, Insights, Workflows, SSO/SAML nem outros recursos da edição Enterprise; não exige conta nem chave de licença; o código inteiro é MIT, sem divisão "open core"; e é mantido pela comunidade. Não existe versão hospedada: você roda na sua infraestrutura.

Principais recursos

  • Páginas de agendamento com tipos de evento e disponibilidade.
  • Integração com calendários (configurável depois em Settings > Integrations).
  • Videochamada via Daily.co.
  • Imagem Docker oficial (inclusive ARM).
  • Assistente de configuração no primeiro acesso.
  • Notificações push (chaves VAPID).

Pré-requisitos

  • Node.js 18+, PostgreSQL 13+ e Yarn (para rodar do código).
  • Ou Docker e Docker Compose.
  • Conhecimento de administração de servidor, banco de dados e segurança.

Instalação

Docker Compose (recomendado)

git clone --recursive https://github.com/calcom/cal.diy.git
cd cal.diy
cp .env.example .env
openssl rand -base64 32    # valor para NEXTAUTH_SECRET
openssl rand -base64 24    # valor para CALENDSO_ENCRYPTION_KEY
npx web-push generate-vapid-keys   # NEXT_PUBLIC_VAPID_PUBLIC_KEY e VAPID_PRIVATE_KEY
docker compose up -d       # Postgres + app + Prisma Studio

Abra http://localhost:3000; o assistente cria o primeiro usuário. Se o passo "Connect your Calendar" travar, vá direto a /event-types. Imagem no Docker Hub: calcom/cal.diy (em ARM, use a tag {version}-arm).

Desenvolvimento local

git clone https://github.com/calcom/cal.diy.git
cd cal.diy
yarn
yarn dx      # sobe Postgres local com usuários de teste (requer Docker)

No Windows, clone pelo Git Bash como administrador com git clone -c core.symlinks=true https://github.com/calcom/cal.diy.git e troque o symlink packages/prisma/.env por uma cópia real (rm packages/prisma/.env && cp .env packages/prisma/.env).

Comandos e uso

yarn dev                                     # modo desenvolvimento
yarn build && yarn start                     # build de produção
yarn workspace @calcom/prisma db-deploy      # migrações em produção
yarn db-studio                               # Prisma Studio (ver/editar o banco)
docker compose down && docker compose pull   # atualizar a versão Docker

Quando usar

  • Ter um "Calendly" próprio, sem mensalidade, para uso pessoal.
  • Estudar ou customizar uma plataforma de agendamento completa e MIT.

Observações

  • O próprio projeto avisa: uso por sua conta e risco, recomendado para uso pessoal e não produtivo. Para uso comercial e empresarial, eles indicam o Cal.com.
  • Troque obrigatoriamente os segredos padrão (NEXTAUTH_SECRET, CALENDSO_ENCRYPTION_KEY) antes de expor na internet.
  • Os usuários de teste do yarn dx (ex.: admin@example.com) são só para desenvolvimento; nunca use em produção.
  • A ficha cobre o README até a seção de Docker; a lista de integrações e variáveis de ambiente não foi detalhada aqui.
