O que é

O xtool é uma ferramenta de linha de comando que replica as funções do Xcode usando padrões abertos. Com ele dá para desenvolver apps iOS sem um Mac: no Linux ou no Windows, pelo WSL. Você escreve o app como um pacote Swift (SwiftPM), e o xtool empacota o pacote como app iOS. Em seguida ele se conecta à conta Apple Developer, registra o iPhone, gera certificado, App ID e perfil de provisionamento, assina o app e instala no aparelho pelo USB.

No macOS ele também serve, para quem quer um fluxo declarativo, só com SwiftPM, sem projeto .xcodeproj. O projeto também traz a biblioteca XKit, para usar os Apple Developer Services e conversar com dispositivos iOS a partir do seu próprio código.

Principais recursos

  • Compila um pacote SwiftPM como app iOS (xtool dev).
  • Assina e instala o app no iPhone ou iPad conectado por USB, com provisionamento automático.
  • Instala, desinstala e abre apps e arquivos .ipa no aparelho.
  • Comandos para os Apple Developer Services (xtool ds).
  • Gera o SDK iOS do Swift a partir do Xcode.xip, no Linux.
  • Integração com IDE (VS Code e outras) via SourceKit-LSP e Build Server Protocol: autocompletar e documentação ao passar o mouse.
  • Suporte a App Extensions, como widgets e share extensions.
  • Biblioteca XKit, para usar como dependência SwiftPM.

Pré-requisitos

Linux ou Windows (WSL):

  • No Windows: WSL com repasse de USB (USBIPD), para o WSL enxergar o iPhone.
  • Toolchain do Swift 6.4, instalada pelo swift.org/install/linux.
  • usbmuxd, para falar com o aparelho; no Ubuntu/Debian, sudo apt-get install usbmuxd. O pacote libimobiledevice-utils (que traz o ideviceinfo) é opcional, mas ajuda.
  • O arquivo Xcode 27.1 (Xcode.xip), baixado pelo navegador em developer.apple.com/download/all. Exige login com Apple ID e aceitar a licença.

macOS:

  • Xcode instalado e aberto ao menos uma vez (ele fornece o SDK iOS e a toolchain).

Os dois casos:

  • Um Apple ID. Pode ser gratuito; com o Apple Developer Program pago, a autenticação usa a API oficial.
  • Um iPhone ou iPad com cabo USB.

Instalação

Linux / WSL

Baixe o AppImage do último release para a sua arquitetura e coloque no PATH:

curl -fL \
  "https://github.com/xtool-org/xtool/releases/latest/download/xtool-$(uname -m).AppImage" \
  -o xtool
chmod +x xtool
sudo mv xtool /usr/local/bin/
xtool --help

macOS

brew install xtool-org/tap/xtool

Outra opção é baixar o xtool.app do último release, mover para /Applications, abrir o app e rodar o script que ele sugere para colocar o xtool no PATH. Nesse caso, as atualizações são manuais.

Configuração inicial (uma vez)

xtool setup
  1. Escolha o modo de login:
    • 0, API Key: recomendado para quem tem o Apple Developer Program pago. Usa a API pública do App Store Connect, com uma Team Key de papel App Manager.
    • 1, Password: funciona com qualquer Apple ID, mas usa APIs privadas da Apple.
  2. No Linux, informe o caminho do Xcode.xip, por exemplo ~/Downloads/Xcode_27.1.xip. O xtool extrai o arquivo e gera o SDK iOS.
  3. Confira com swift sdk list. A saída deve listar darwin.

Comandos e uso

xtool new Hello      # cria um projeto SwiftPM a partir do template (Package.swift, xtool.yml, Sources/...)
cd Hello
xtool dev            # compila, assina e instala no aparelho conectado
xtool devices        # lista os aparelhos conectados
xtool install app.ipa   # instala um .ipa no aparelho
xtool uninstall      # desinstala um app
xtool launch         # abre um app instalado
xtool auth           # gerencia o login nos Apple Developer Services
xtool sdk            # gerencia o SDK Darwin do Swift
xtool ds             # comandos dos Apple Developer Services
xtool help <subcomando>   # ajuda detalhada

O xtool.yml define como o pacote vira app. O mínimo é o Bundle ID:

version: 1
bundleID: com.example.Hello

Primeira execução do xtool dev:

  1. A primeira compilação demora alguns minutos, porque compila os módulos do SDK iOS. As seguintes são rápidas.
  2. No iPhone, toque em Confiar (Trust) e digite o código. Se o xtool der erro nesse ponto, rode o comando de novo.
  3. Se o iPhone pedir, ative o Modo de Desenvolvedor e rode o comando de novo.
  4. Ao abrir o app pela primeira vez, vá em Ajustes > Geral > VPN e Gerenciamento de Dispositivos > [seu e-mail] > Confiar.

Usar como biblioteca (XKit):

.package(url: "https://github.com/xtool-org/xtool", .upToNextMinor(from: "1.2.0"))
.product(name: "XKit", package: "xtool")

Quando usar

  • Desenvolver e testar apps iOS no seu iPhone sem ter um Mac.
  • Fazer build de apps iOS em CI ou em servidores Linux.
  • Editar apps iOS no VS Code, no Windows (via WSL) ou no Linux, com autocompletar.
  • No Mac, manter projetos iOS só com SwiftPM, sem arquivos .xcodeproj.

Observações

  • Credenciais Apple: o modo Password usa APIs privadas da Apple. A própria documentação sugere criar um Apple ID descartável por precaução. O projeto afirma que as credenciais só vão para a Apple.
  • Apple ID gratuito: com conta gratuita valem os limites da Apple para assinatura de desenvolvimento, como validade curta do perfil e número limitado de apps e dispositivos. Para publicar na App Store, você precisa do Developer Program pago.
  • Licença do Xcode: no Linux, o SDK sai do Xcode.xip oficial, que você baixa aceitando os termos da Apple.
  • WSL: se aparecer AFCClient.Error.muxError, a documentação indica uma alternativa: repassar a conexão pelo iTunes do Windows, conforme a issue #19.
  • A versão exigida do Swift e do Xcode muda conforme o release. Confira o guia de instalação antes de atualizar. O último release é o 1.24.0, de out/2026.
