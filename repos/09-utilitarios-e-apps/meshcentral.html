O que é

O MeshCentral é um site completo de gerenciamento de computadores que você hospeda no seu próprio servidor. O fluxo é:

  1. suba o servidor;
  2. crie um grupo de dispositivos;
  3. baixe e instale o agente (MeshAgent) em cada máquina.

Um minuto depois a máquina aparece no painel, e dá para assumir o controle dela pelo navegador. Não há serviço de terceiros no meio: o tráfego passa pelo seu servidor.

Principais recursos

  • Pelo navegador: área de trabalho remota, terminal e gerenciamento de arquivos.
  • Três modos de rede:
    • LAN (padrão): os agentes acham o servidor por multicast na rede local, sem IP fixo nem DNS;
    • WAN e híbrido: para gerenciar máquinas pela internet, com um nome DNS ou IP fixo.
  • Agentes para Windows, Linux, macOS e Android. Também gerencia máquinas com Intel AMT, inclusive pelo CIRA.
  • Contas e acesso:
    • vários usuários e grupos de dispositivos;
    • autenticação em dois fatores (TOTP e Duo);
    • SSO e OpenID Connect;
    • limite de tentativas de login;
    • filtro de IP.
  • Servidor:
    • TLS com Let's Encrypt e suporte a proxy reverso (NGINX e outros);
    • e-mail e SMS;
    • marca própria e termos de uso;
    • HashiCorp Vault;
    • plugins.
  • Bancos de dados: NeDB embutido (padrão), MongoDB, PostgreSQL, MariaDB e MySQL.
  • Ferramentas do ecossistema:
    • MeshCtrl: linha de comando para automatizar a administração;
    • MeshCentral Router: mapeamento de portas TCP através do agente;
    • MeshCmd.
  • Leve: um Raspberry Pi ou uma instância AWS t3.nano gerencia algumas centenas de dispositivos.

Pré-requisitos

  • Node.js 20+ e npm. No Windows, o instalador gráfico instala o Node se faltar.
  • Ou Docker/Podman, com a imagem ghcr.io/ylianst/meshcentral.
  • Portas padrão:
    • TCP 80 (HTTP), 443 (HTTPS) e 4433 (Intel AMT CIRA);
    • UDP 16990 (descoberta na LAN e no modo híbrido).
  • Acesso à internet na primeira partida. O servidor baixa do GitHub os instaladores dos agentes (cerca de 120 MiB). Em servidor sem internet, copie-os à mão (veja Agent Downloads).
  • Para uso pela internet: um nome DNS ou IP público fixo.

Instalação

Com npm (qualquer sistema):

mkdir -p /opt/meshcentral
cd /opt/meshcentral
npm install meshcentral          # não use sudo neste comando
node node_modules/meshcentral    # inicia o servidor (modo LAN por padrão)

Para rodar como serviço em segundo plano, inicie com --install. Use --help para ver as opções.

Windows: o instalador do MeshCentral instala o Node.js se precisar, cria o serviço do Windows e abre as portas no Firewall do Windows Defender. Na instalação ele pergunta:

  • Multi-user Server: se marcado, o servidor fica aberto e os usuários podem criar contas. Desmarcado, é monousuário, sem tela de login e acessível só da própria máquina.
  • Auto-update Server: atualização diária automática, entre 00:00 e 01:00.
  • Server Mode: LAN ou WAN/híbrido. No WAN, informe o DNS ou IP público; se estiver errado, os agentes não conectam.

Docker:

docker run -d \
  --name meshcentral \
  --restart unless-stopped \
  -p 80:80 \
  -p 443:443 \
  -v data:/opt/meshcentral/meshcentral-data \
  -v user_files:/opt/meshcentral/meshcentral-files \
  -v backup:/opt/meshcentral/meshcentral-backups \
  -v web:/opt/meshcentral/meshcentral-web \
  ghcr.io/ylianst/meshcentral:latest

As tags são:

  • latest: último release;
  • master: último commit;
  • uma versão fixa, como 1.3.1.

Também há variantes -slim (NeDB), -mongodb, -postgresql e -mysql. Em contêiner, não use a atualização embutida: atualize trocando a imagem.

Instalação endurecida (Debian/Ubuntu): o guia Secure roda o servidor com um usuário de sistema sem login (meshcentral) e o código em modo só leitura. O custo:

  • a atualização automática para; atualize à mão com sudo npm install meshcentral;
  • é preciso um banco externo, como o MongoDB.

Comandos e uso

  1. Abra o endereço do servidor no navegador e crie logo a primeira conta: ela vira a administradora do servidor.
  2. Crie um grupo de dispositivos, baixe o instalador do agente desse grupo e rode-o em cada máquina.
  3. Clique no dispositivo para abrir a área de trabalho remota, o terminal ou os arquivos.

A configuração fica em meshcentral-data/config.json. Ela precisa ser um JSON válido, e as chaves não diferenciam maiúsculas de minúsculas. Exemplos do repositório:

  • config simples;
  • config avançada;
  • schema completo.

É no config.json que se troca para o modo WAN (definindo o nome DNS), se configura e-mail ou SMS, a marca e o banco de dados.

node node_modules/meshcentral --help        # opções do servidor (serviço, etc.)
node ./node_modules/meshcentral/meshctrl    # MeshCtrl: lista as ações disponíveis

O MeshCtrl entra no servidor por WebSocket, com um usuário ou administrador. Ele lista, cria e remove contas, lista grupos de dispositivos e automatiza tudo o que o site faz. Veja o guia do MeshCtrl.

Quando usar

  • Suporte remoto e administração de muitos computadores (TI interna, MSP) sem depender de serviço de terceiros.
  • Gerenciar máquinas na LAN sem DNS nem IP fixo, ou pela internet com o servidor exposto.
  • Parques com Intel AMT, para gerenciamento fora de banda.
  • Comparação no catálogo:
    • o RustDesk é focado em acesso remoto ponto a ponto, no estilo TeamViewer, com servidor próprio opcional;
    • o MeshCentral é uma plataforma RMM completa, toda pelo navegador, com grupos, usuários, agentes permanentes e automação;
    • o TwinDesk une seus próprios aparelhos numa mesa só e não serve para administrar terceiros.

Observações

  • É uma ferramenta de acesso total às máquinas. Quem controla o servidor ou uma conta de administrador controla todos os agentes instalados.
  • Proteja o servidor:
    • crie a conta de administrador assim que subir o servidor: a primeira conta criada vira admin;
    • no modo Multi-user, desative o cadastro aberto se não precisar dele;
    • ative 2FA;
    • use TLS (Let's Encrypt ou proxy reverso);
    • limite as tentativas de login e filtre IPs.
  • Agentes estranhos no painel: o FAQ explica um caso comum, que não é invasão. Antivírus que enviam executáveis desconhecidos para análise rodam o instalador do agente nos seus sandboxes, e a máquina deles aparece no seu painel. A recomendação é não deixar o servidor aberto para qualquer um na internet.
  • Instale agentes só em máquinas próprias ou com autorização do dono. Acesso remoto sem consentimento é crime no Brasil (art. 154-A do Código Penal). Monitorar estações de funcionários exige política clara e base legal na LGPD.
  • O instalador do agente pode ser apontado como suspeito por antivírus. A documentação tem uma seção sobre assinatura de código.
  • O NeDB padrão serve para começar. Para mais desempenho, use MongoDB ou PostgreSQL.
  • 2FA por TOTP falha se o relógio do servidor ou do celular estiver errado. Confira o NTP.
  • Projeto ativo, com último release 1.3.1 (out/2026). A documentação fica no repositório separado MeshCentralDocs.
