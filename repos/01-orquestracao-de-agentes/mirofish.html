O que é

O MiroFish é um motor de previsão multiagente. Você envia materiais-semente (notícias, rascunhos de política, sinais financeiros, relatórios ou até uma história) e descreve em linguagem natural o que quer prever. O sistema constrói um mundo digital paralelo de alta fidelidade, no qual milhares de agentes com personalidade, memória de longo prazo e lógica de comportamento interagem e evoluem socialmente.

Você pode injetar variáveis de uma "visão de Deus" para explorar trajetórias futuras. O resultado é um relatório de previsão detalhado e um mundo simulado com o qual dá para conversar. A simulação usa o motor OASIS, da CAMEL-AI.

É útil como laboratório de ensaio para decisões (políticas, comunicação) e como sandbox criativo.

Principais recursos

  • Construção de grafo a partir das sementes, com injeção de memória individual e coletiva e GraphRAG.
  • Geração de personas e configuração de agentes.
  • Simulação paralela em duas plataformas, com atualização temporal da memória.
  • ReportAgent com conjunto de ferramentas para interagir com o ambiente pós-simulação.
  • Conversa com qualquer agente do mundo simulado.
  • Demo online e exemplos (simulação de opinião pública e final perdido de "Sonho da Câmara Vermelha").
  • Implantação por código-fonte ou Docker.

Pré-requisitos

  • Node.js 18 ou superior.
  • Python 3.11 ou superior e até 3.12.
  • uv (gerenciador de pacotes Python).
  • Chave de API de um LLM compatível com o formato OpenAI SDK (o README recomenda o Qwen-plus via Alibaba Bailian).
  • Chave de API da Zep Cloud (há cota mensal gratuita).

Instalação

Opção 1: código-fonte (recomendada)

  1. Configure as variáveis de ambiente:
cp .env.example .env
  1. Preencha o .env:
LLM_API_KEY=your_api_key
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL_NAME=qwen-plus
ZEP_API_KEY=your_zep_api_key

O .env.example também tem um bloco opcional de "LLM acelerado" (LLM_BOOST_API_KEY, LLM_BOOST_BASE_URL, LLM_BOOST_MODEL_NAME). Se não for usar esse bloco, apague as três linhas do .env: elas não podem ficar em branco.

  1. Instale as dependências:
npm run setup:all

Ou em etapas: npm run setup e npm run setup:backend.

  1. Inicie os serviços:
npm run dev

Frontend em http://localhost:3000 e API em http://localhost:5001.

Opção 2: Docker

cp .env.example .env
docker compose up -d

Usa a imagem ghcr.io/666ghj/mirofish:latest, lê o .env da raiz, mapeia as portas 3000 (frontend) e 5001 (backend) e guarda os arquivos enviados em ./backend/uploads. Se o download da imagem estiver lento, o docker-compose.yml traz, em comentário, um endereço alternativo.

Comandos e uso

npm run backend

Sobe apenas o backend.

npm run frontend

Sobe apenas o frontend.

Fluxo na interface: envie os materiais-semente, descreva a pergunta de previsão em linguagem natural, acompanhe a simulação, leia o relatório e converse com os agentes ou com o ReportAgent.

Quando usar

  • Testar o impacto provável de uma decisão, política ou comunicado antes de publicar.
  • Explorar cenários "e se" a partir de notícias ou relatórios.
  • Experimentos criativos, como imaginar finais alternativos de uma história.

Observações

  • Licença AGPL-3.0: obrigações de código aberto se você oferecer o software como serviço em rede.
  • O consumo de tokens é alto; o README recomenda começar com menos de 40 rodadas de simulação.
  • Depende de serviços externos (LLM e Zep Cloud).
  • O README é bilíngue (inglês e chinês); a comunidade e o contato são voltados ao público chinês.
