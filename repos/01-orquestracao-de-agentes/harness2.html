O que é

Harness é tudo o que fica em volta do modelo e o transforma num agente: prompt de sistema, ferramentas, memória, skills, subagentes, regras e orquestração. Ajustar esse conjunto é chamado de harnessing. O Harness² é um framework do Google Research que faz esse ajuste automaticamente e de forma recursiva, inclusive para tarefas que não existiam quando o harness foi desenhado. Os pesos do modelo não mudam.

Ele trabalha em dois níveis:

  • Por tarefa: um ciclo Propor → Testar → Compor sugere alterações no harness, executa a mesma tarefa com cada variação e monta um harness melhor comparando o comportamento das execuções, sem precisar saber a resposta certa.
  • Entre tarefas: guarda os harnesses adotados e as lições confirmadas por evidência num improvement harness persistente, que orienta as próximas melhorias.

Segundo o artigo, um único ciclo melhorou o GLM-5 e o Gemini 3.5 Flash em três benchmarks profissionais: até 11,5 pontos no WorkBuddy-Bench, 4,5 no JobBench e 11,8 pontos percentuais no LAB (tarefas jurídicas). Mais ciclos trazem ganhos adicionais.

Principais recursos

  • Oito componentes editáveis do harness: prompt de sistema, guardrails, memória, orientação de ferramentas, subagentes, skills, scripts e plugins.
  • Dois modos de recursão: paralelo, que testa várias variações ao mesmo tempo e explora mais, e sequencial, que refina passo a passo e aprofunda mais.
  • Executores OpenCode (padrão) e Codex.
  • Benchmarks prontos: JobBench (trabalho profissional), LAB (jurídico) e WorkBuddy-Bench (escritório, web e código).
  • Demonstração local que não precisa de credenciais de modelo.
  • Resultados salvos em runs/: entregáveis, harnesses adotados, notas de reflexão e avaliações. Para retomar uma execução, basta repetir o comando.

Pré-requisitos

  • Linux, Python 3.12 e uv. No Windows, use o WSL.
  • Para benchmarks com modelos: Node.js 20+ e Google Cloud CLI (gcloud). O LAB também precisa de Pandoc e Poppler, e o WorkBuddy-Bench precisa de Docker.
  • Acesso a modelos. A configuração pronta usa Vertex AI (Gemini como executor e juiz; Claude ou Gemini no Vertex como "melhorador"). O executor Codex aceita outro endpoint compatível com a Responses API, configurado com HARNESS2_CODEX_API_KEY e HARNESS2_CODEX_MODEL.

Instalação

Na raiz do repositório clonado:

uv venv --python 3.12 .venv
source .venv/bin/activate
uv pip install -e '.[render]'
harness2-demo --output runs/demo --k 2     # demo local, sem chave de modelo

Para rodar com modelos de verdade:

cp .env.example .env
# edite o .env com o projeto do Vertex AI e os IDs dos modelos
gcloud auth application-default login

Variáveis principais do .env:

  • HARNESS2_SOLVER_MODEL: modelo executor, no formato provider/model do OpenCode.
  • HARNESS2_IMPROVER_MODEL: modelo que melhora o harness. Se ficar vazio, usa o mesmo do executor.
  • HARNESS2_JUDGE_MODEL: modelo juiz.

Outras formas de autenticação e o executor Codex estão no guia de setup.

Comandos e uso

Exemplo com o benchmark LAB, rodando uma tarefa só:

harness2-setup lab                          # instala o benchmark
harness2-check --bench lab                  # confere as dependências (não testa os modelos)
harness2 --bench lab --k 1 --mode parallel \
  --only-domains antitrust-competition --max-tasks 1   # roda o ciclo de melhoria
harness2-judge --bench lab --k 1 --mode parallel       # avalia o resultado
harness2-report --bench lab --k 1 --mode parallel      # gera o relatório
Opção O que faz
--k 1 Um ciclo Propor → Testar → Compor
--k K --mode parallel Testa K variações gerais e K específicas do domínio e gera K composições
--k K --mode sequential Refina o harness em K ciclos seguidos
--substrate cx Usa o Codex no lugar do OpenCode
--dry-run Mostra quais tarefas seriam executadas, sem chamar modelos

Outros benchmarks: harness2-setup jb (JobBench) e harness2-setup wb (WorkBuddy-Bench, que aceita --subset office, web ou code). Os comandos de avaliação e relatório precisam usar o mesmo benchmark, executor, subconjunto, --k, --mode e seed da execução. Todos os comandos aceitam --help.

Quando usar

  • Pesquisa e experimentos sobre como melhorar agentes de IA sem fine-tuning.
  • Comparar, com evidências, mudanças no seu harness: prompts, skills, subagentes. O Vibe Coding Toolkit traz um guia de uso do Harness2 para esse fim.
  • Ter ideias para melhorar o seu próprio setup de agentes, como CLAUDE.md, skills e hooks, a partir das lições que o framework registra.

Observações

  • É um projeto de pesquisa, não uma ferramenta pronta para o dia a dia. O próprio README diz que não é um produto oficialmente suportado pelo Google.
  • Gera custo de API: cada ciclo executa a tarefa várias vezes. Comece com --max-tasks 1 e --dry-run.
  • Segurança: os executores têm acesso livre à rede, e o Codex roda com o sandbox desligado. Rode numa VM ou container isolado e configure as restrições de rede antes de avaliar, para o agente não achar as respostas dos benchmarks online.
  • Projeto muito recente (criado em out/2026), ainda sem releases publicadas.
  • Ao trocar de modelo ou de seleção de tarefas, use um HARNESS2_RUNS_DIR novo para não misturar resultados.
