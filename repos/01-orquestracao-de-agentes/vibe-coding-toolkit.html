O que é

O Vibe Coding Toolkit é uma coleção de documentação, prompts e templates com duas funções: configurar máquinas e configurar projetos individuais para trabalhar com agentes de IA. Você descreve o objetivo; o agente inspeciona o ambiente, organiza as decisões, configura os componentes aplicáveis e verifica o resultado. O código fica no seu projeto, e o repositório guarda apenas a "receita".

O uso é feito colando no agente (com acesso a arquivos e terminal) um prompt curto que aponta para um arquivo do repositório. Os guias cobrem Claude Code e Codex separadamente; outros clientes podem seguir os mesmos acordos se tiverem capacidades equivalentes. O README está em inglês, português do Brasil e espanhol.

O fluxo de trabalho proposto é: entender, projetar, planejar quando preciso, implementar, verificar e revisar. O kit reúne ferramentas como Superpowers, Ponytail, Caveman, RTK, Context7 e Graphify, além de regras de qualidade (ESLint com limite de 350 linhas por arquivo) e orquestração de subagentes em ondas paralelas.

Principais recursos

  • Prompt de preparação da máquina (runtime, Docker, agentes, plugins, integrações, backups e manifesto).
  • Prompt de bootstrap de projeto novo com Next.js (App Router, TypeScript, Tailwind, ESLint, Drizzle/PostgreSQL, Zod, Pino, Vitest).
  • Prompt de configuração ou atualização de projeto existente, preservando a stack e os contratos atuais.
  • Protocolo de orquestração de subagentes (um escritor por arquivo, revisores somente leitura, limites de tentativas).
  • Biblioteca de prompts numerados: saneamento, ESLint, revisão multiagente, brainstorm até plano, memória, revisão de segurança, avaliação e melhoria do harness.
  • Documentos-padrão do projeto: README.md, PRODUCT.md, AGENTS.md, CLAUDE.md e cinco arquivos em docs/.
  • Adoção modular: dá para instalar só um componente (por exemplo, os quality gates).
  • Validação documentada em macOS, Linux e Windows, com CI em Ubuntu e Windows.

Pré-requisitos

  • Um agente com permissão para ler arquivos, editar e executar comandos (Claude Code ou Codex). Uma conversa sem acesso ao ambiente só explica o processo e não prova instalações nem testes.
  • Para projetos novos, o foco é Next.js; em projetos existentes a stack é preservada.
  • Os demais requisitos (Node.js, Docker, Git etc.) são verificados e instalados pelo próprio prompt de preparação da máquina.

Instalação

Não há pacote para instalar: o uso é colar um prompt no agente. Os comandos abaixo estão no README.

Preparar a máquina

Read https://raw.githubusercontent.com/soumatheusgomes/vibe-coding-toolkit/main/docs/prompts/10-development-environment-setup.md and execute the entire "Prompt" section block on this computer.

Iniciar um projeto novo

Abra o agente na pasta de destino e cole (troque a segunda linha pela descrição do seu produto):

Read https://raw.githubusercontent.com/soumatheusgomes/vibe-coding-toolkit/main/docs/prompts/11-next-project-bootstrap.md and execute setup in this directory.
Project: [name, problem, audience, main flows, and constraints].

Configurar ou atualizar um projeto existente

Abra o agente na raiz da aplicação e cole:

Read https://raw.githubusercontent.com/soumatheusgomes/vibe-coding-toolkit/main/docs/prompts/12-existing-project-setup.md and execute the entire "Prompt" section block in this project, starting with brainstorming.

Reexecutar o prompt faz parte da manutenção: ele confere a revisão do kit e preserva personalizações. Se você estiver com um checkout local, use o arquivo local em vez da URL.

Comandos e uso

# Instalar só os quality gates (ESLint com limite de linhas por arquivo)
Read https://raw.githubusercontent.com/soumatheusgomes/vibe-coding-toolkit/main/docs/prompts/08-eslint-quality-gates-install.md and execute the prompt in this project. Use MAX_LINES=350.

Outros prompts do catálogo (em docs/prompts/):

  • 01-project-sanitation.md: mede problemas e saneia o projeto.
  • 03-multi-agent-code-review.md: revisão por especialistas.
  • 04-brainstorm-to-plan.md: transforma um pedido ambíguo em trabalho com critérios de aceite.
  • 05-parallel-wave-dispatch.md: execução independente em ondas paralelas.
  • 09-file-size-refactor.md: refatora arquivos grandes por responsabilidade.
  • 13-security-review.md: revisão de segurança somente leitura, com relatório privado.
  • 14-harness-evaluation.md e 15-harness-improvement.md: avaliam e melhoram o harness após mudanças.

Guias de ferramentas opcionais (em docs/tools/), ativadas só quando servem ao projeto: next-dev-loop e next-bundle-optimizer (Next.js), PostgreSQL, conserto de CI do GitHub Actions, revisão de segurança diferencial, shadcn/ui, Sentry MCP e Harness2.

Para validar uma cópia clonada do próprio toolkit:

node --test scripts/validate-docs.test.mjs   # testa o validador
node scripts/validate-docs.mjs               # confere links, âncoras e JSON da documentação
node scripts/validate-next.mjs               # cria um projeto Next.js temporário e roda as checagens (exige Node.js 24, npm e internet)

O que fica na máquina e o que fica no projeto

Máquina e cliente Projeto
Runtime, Git e gerenciador de pacotes Dependências da aplicação e lockfile
Agente, autenticação e plugins já instalados Produto, instruções e documentação específica
RTK Skills locais e skills-lock.json
Ponytail, Caveman e Superpowers Regras de qualidade e comandos canônicos
Graphify CLI e conexão do Context7 Exclusões do grafo e configuração local

Em projeto existente, o toolkit preserva framework, gerenciador de pacotes, banco, ORM e testes, e mede antes de mudar. Em monorepo, identifica os workspaces antes de escolher onde aplicar.

Quando usar

  • Padronizar o ambiente de desenvolvimento com agentes de IA em uma máquina nova.
  • Começar um projeto Next.js já com documentação, regras de qualidade e instruções para agentes.
  • Adotar boas práticas de harness (AGENTS.md, memória, skills, verificação) em um projeto que já existe.
  • Reaproveitar prompts prontos de saneamento, revisão e refatoração.

Observações

  • Os atalhos remotos usam a versão publicada na branch main. O prompt manda o agente instalar e alterar coisas na máquina e no projeto, então vale ler o arquivo do prompt antes de executar, mesmo sendo um conteúdo público.
  • Os padrões são revisados contra fontes atuais durante a execução; o resultado pode variar entre rodadas.
  • O repositório é recente e muito ativo (último push em out/2026), então o conteúdo muda com frequência.
  • Não é um gerador nem uma aplicação pronta: projetos novos saem do create-next-app e os templates complementam a base. Publicar, usar serviços pagos ou fazer migrações incompatíveis exige autorização sua.
  • É montado sobre outros projetos (Superpowers, RTK, Ponytail, Caveman, Graphify, Context7, agent-browser, Vercel Agent Skills e Skills CLI), cada um com a própria licença.
