O que é

O Evolution Go é uma API REST para integrar WhatsApp a sistemas, construída em Go sobre a biblioteca whatsmeow. Faz parte do ecossistema da Evolution Foundation e é usado como provedor de WhatsApp pelo Evo CRM Community e por outros projetos da casa.

A proposta é consumir poucos recursos: um serviço em Go, com banco PostgreSQL, eventos em tempo real (WebSocket, Webhook, RabbitMQ e NATS) e armazenamento de mídia em MinIO/S3. A documentação da API é gerada em Swagger.

Diferença para a Evolution API (Node.js)

Já existe a ficha da Evolution API, a versão original em TypeScript/Node.js. As duas são "irmãs" e têm o mesmo objetivo, mas não são intercambiáveis:

Evolution API Evolution Go
Linguagem TypeScript (Node.js 20+) Go 1.24+
Biblioteca de WhatsApp Baileys (e também a Cloud API oficial da Meta) whatsmeow
Banco PostgreSQL ou MySQL (Prisma) e Redis PostgreSQL (GORM)
Integrações prontas Chatwoot, Typebot, OpenAI, Dify, Flowise, N8N Não listadas no README; foco em API e eventos
Filas/eventos WebSocket, RabbitMQ, Kafka, SQS, NATS, Pusher WebSocket, Webhook, RabbitMQ, NATS
Licença de uso Apache 2.0 com condições de marca Apache 2.0 com condições de marca e exige licença ativada
Maturidade ~9,9k estrelas, mais recursos ~940 estrelas, mais recente e mais enxuta

Quando usar cada uma:

  • Evolution API: quando você precisa da Cloud API oficial da Meta, de integrações nativas com Chatwoot/Typebot/Dify/OpenAI, ou de um ecossistema com mais exemplos e comunidade.
  • Evolution Go: quando o foco é desempenho e baixo consumo de recursos, e você aceita o fluxo de ativação de licença. O README não menciona suporte à Cloud API oficial nem às integrações de chatbot; confirme na documentação se algo disso é requisito.

Principais recursos

  • Alto desempenho e baixo uso de recursos (Go).
  • API REST com Swagger (/swagger/index.html).
  • Eventos em tempo real: WebSocket, Webhook, AMQP/RabbitMQ e NATS.
  • Mídia (imagens, vídeos, áudio, documentos) com MinIO/S3.
  • Persistência opcional de mensagens no PostgreSQL.
  • Pareamento por QR code embutido.
  • Painel Manager em /manager/login.
  • Gerenciamento de licença embutido (registro, ativação e heartbeat).
  • Configuração de produção em Docker.

Pré-requisitos

  • Go 1.24+ para rodar a partir do código-fonte.
  • PostgreSQL (dois bancos nos exemplos do .env: evogo_auth e evogo_users).
  • Docker e make, para o caminho recomendado.
  • Opcionais: RabbitMQ, NATS e MinIO/S3.

Instalação

Docker (recomendado pelo README)

git clone https://github.com/evolution-foundation/evolution-go.git
cd evolution-go
make docker-build
make docker-run

Também existe a imagem evoapicloud/evolution-go no Docker Hub (o README só a cita no selo e na tabela de links).

Desenvolvimento local

git clone https://github.com/evolution-foundation/evolution-go.git
cd evolution-go
make setup
cp .env.example .env
make dev

make help lista os comandos; detalhes em COMMANDS.md. No Windows, o make não vem instalado por padrão; o README não traz instruções específicas para Windows, então use WSL ou Docker.

Configuração mínima (.env)

SERVER_PORT=8080
CLIENT_NAME=evolution
GLOBAL_API_KEY=troque-por-uma-chave-segura
POSTGRES_AUTH_DB=postgresql://postgres:senha@localhost:5432/evogo_auth?sslmode=disable
POSTGRES_USERS_DB=postgresql://postgres:senha@localhost:5432/evogo_users?sslmode=disable
DATABASE_SAVE_MESSAGES=false

Variáveis opcionais: AMQP_URL, NATS_URL, WEBHOOK_URL e as do MinIO (MINIO_ENABLED, MINIO_ENDPOINT etc.).

Ativação da licença

  1. Suba o servidor (a API responde 503 até a ativação).
  2. Abra o Manager em http://localhost:8080/manager/login.
  3. Informe a URL da API e a GLOBAL_API_KEY.
  4. Conclua o fluxo de registro de licença.

O estado fica na tabela runtime_configs e há heartbeats periódicos para manter a ativação.

Comandos e uso

make help            # lista os comandos disponíveis
make dev             # sobe em modo desenvolvimento
make docker-build    # constrói a imagem Docker
make docker-run      # executa o container

Endpoints principais (autenticados com a GLOBAL_API_KEY):

POST   /instance/create             # cria uma instância de WhatsApp
GET    /instance/{name}/qrcode      # QR code para parear
GET    /instance/{name}/status      # status da instância
POST   /message/sendText            # envia texto
POST   /message/sendMedia           # envia mídia
DELETE /instance/{name}             # remove a instância

Quando usar

  • Enviar e receber WhatsApp por API com baixo consumo de CPU e memória.
  • Servir como provedor de WhatsApp para o Evo CRM Community.
  • Receber eventos em filas (RabbitMQ ou NATS) ou webhooks para automações próprias.

Observações

  • Exige ativação de licença: sem ela, a API devolve 503. O README não detalha custos nem termos do registro; consulte o site da Evolution Foundation antes de adotar.
  • A licença é Apache 2.0 com condições adicionais (preservar logo/copyright e aviso de uso). Leia o LICENSE e o TRADEMARKS.md antes de uso comercial ou revenda.
  • Coleta telemetria anônima (rotas usadas e versão da API).
  • Como toda API não oficial baseada em WhatsApp Web (whatsmeow), há risco de bloqueio de números e de quebra por mudanças do WhatsApp. Atenção também à LGPD ao armazenar mensagens (DATABASE_SAVE_MESSAGES).
  • O README cita um parceiro de hospedagem (HostGator); isso é opcional.
