O que é

O Chatwoot é uma central de atendimento open source e self-hosted. Ele reúne em uma única caixa de entrada as conversas de vários canais: chat ao vivo no site, e-mail, Facebook, Instagram, Twitter, WhatsApp, Telegram, Line, SMS e outros.

Você mantém controle total dos dados dos clientes, define equipes, atribuições e automações, e pode ampliar a plataforma por API e webhooks. É muito usado em conjunto com APIs de WhatsApp não oficiais (como a Evolution API) para centralizar o atendimento da equipe.

A branch padrão do repositório é develop (modelo git-flow). Para uso estável, o README recomenda a master ou as tags v1.x.x.

Principais recursos

  • Caixa de entrada omnichannel (site, e-mail, redes sociais, WhatsApp, Telegram, SMS e canal via API).
  • Captain, agente de IA para automatizar respostas de suporte.
  • Help Center (portal de artigos e FAQs) embutido.
  • Notas privadas, @menções, etiquetas, respostas prontas e atribuição automática de conversas.
  • Equipes, automações, horário comercial e gestão de capacidade dos agentes.
  • CRM básico: contatos, segmentos, atributos personalizados e campanhas.
  • Integrações: Slack, Dialogflow, Shopify, Linear, Google Translate e Dashboard Apps.
  • Relatórios (conversas, agentes, caixas, etiquetas, equipes e CSAT).

Pré-requisitos

  • Docker com Docker Compose.
  • Postgres (imagem pgvector/pgvector:pg16) e Redis, ambos já definidos no compose de produção.
  • Um domínio e, de preferência, um proxy reverso com HTTPS na frente (a porta 3000 do compose é exposta apenas em 127.0.0.1).
  • Servidor SMTP para envio de e-mails (variáveis SMTP_*).

Instalação

Instalação self-hosted com Docker, usando os arquivos oficiais do repositório (docker-compose.production.yaml e .env.example). O guia completo está na documentação oficial de deploy com Docker.

  1. Baixe o compose de produção e o arquivo de variáveis de ambiente:
wget -O docker-compose.yaml https://raw.githubusercontent.com/chatwoot/chatwoot/develop/docker-compose.production.yaml
wget -O .env https://raw.githubusercontent.com/chatwoot/chatwoot/develop/.env.example
  1. Edite o .env. Pontos principais do .env.example:
    • SECRET_KEY_BASE (troque por uma chave longa e segura);
    • FRONTEND_URL (URL pública da instalação);
    • POSTGRES_PASSWORD e REDIS_PASSWORD (defina senhas);
    • ENABLE_ACCOUNT_SIGNUP (false por padrão);
    • variáveis SMTP_* e MAILER_SENDER_EMAIL para e-mail;
    • RAILS_ENV (o .env.example traz development; o compose de produção já força production nos serviços rails e sidekiq).
  2. No docker-compose.yaml, preencha POSTGRES_PASSWORD do serviço postgres com a mesma senha do .env.
  3. Prepare o banco (a tarefa db:chatwoot_prepare existe em lib/tasks/db_enhancements.rake):
docker compose run --rm rails bundle exec rails db:chatwoot_prepare
  1. Suba os serviços:
docker compose up -d

O compose cria os serviços rails (porta 127.0.0.1:3000), sidekiq, postgres e redis, com volumes persistentes storage_data, postgres_data e redis_data. Configure um proxy reverso (Nginx, Traefik etc.) apontando para a porta 3000 e abra a URL para criar a conta de super administrador.

Outras formas de deploy citadas no README: Heroku (botão one-click), DigitalOcean 1-Click Kubernetes, Helm (Artifact Hub) e a página de deploy.

Comandos e uso

docker compose up -d                          # sobe a stack em segundo plano
docker compose logs -f rails                  # acompanha os logs do app web
docker compose logs -f sidekiq                # acompanha os logs dos jobs em fila
docker compose pull && docker compose up -d   # atualiza a imagem chatwoot/chatwoot:latest

Depois de instalar: crie caixas de entrada (Inboxes) em Configurações, convide agentes e conecte canais como WhatsApp (Cloud API, Twilio ou uma API não oficial como a Evolution API).

Quando usar

  • Centralizar o atendimento de uma equipe em um único painel, com histórico por contato.
  • Ter um helpdesk self-hosted para não depender de SaaS cobrado por agente.
  • Servir de front-end de atendimento para bots e APIs de WhatsApp (Evolution API, Typebot, n8n).

Observações

  • O README declara MIT, mas o GitHub marca a licença como "NOASSERTION" por causa da pasta enterprise/, que tem recursos sob licença própria.
  • Faça backup do volume do Postgres e do storage_data antes de atualizar.
  • Confira o passo a passo atualizado na documentação oficial de self-hosting, pois variáveis e versões mudam.
