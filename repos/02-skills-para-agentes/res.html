O que é

O RES é uma skill para agentes de código (feita para o Claude Code) que estuda um produto web pelo navegador e documenta como ele funciona, para que um time ou outro agente consiga recriá-lo e lançá-lo. A ideia é responder "como o produto funciona para o usuário e o que é preciso para lançar um clone", sem tocar em dados de produção.

O agente explora o produto num ambiente de teste, registra cada alteração que faz e grava o que aprende em arquivos: telas e estados, regras de negócio com evidência, modelo de dados, formato das APIs, design tokens e as barreiras de lançamento (integrações que exigem aprovação, licenças, certificações). Cada afirmação leva uma marca de evidência: [obs] visto no produto, [net] capturado na rede, [doc] da documentação pública ou [inf] inferência com pergunta em aberto.

No fim, entrega dois arquivos: o REPORT.html, um relatório de página única para pessoas, e um zip para o agente de código, que começa pelo BUILD.md. A base de conhecimento em disco é a memória do agente, então um estudo pode durar várias sessões.

Principais recursos

  • Estudo em 7 fases: escopo, ambiente seguro, pesquisa pública, mapa de telas, aprofundamento por funcionalidade, síntese e entrega.
  • Regras de negócio em Given/When/Then com evidência, que viram testes de paridade.
  • Modelo de dados com entidades, enums, relações, diagrama ER e tipos TypeScript.
  • Design tokens (cores, tipografia, espaçamento, sombras, animações) mapeados às variáveis CSS do produto.
  • Análise de barreiras de lançamento com severidade, prazo e mitigação (ex.: verificação da Meta para WhatsApp).
  • Modelo de segurança em 4 níveis (L1 a L4) e registro de todas as alterações em sandbox/ledger.csv, revertidas no fim.
  • Pode rodar sem interrupções: o que precisa de você fica anotado em STATUS.md, em "Needs human".
  • Leve: cerca de 130 tokens por sessão e cerca de 4.600 quando é acionada.

Pré-requisitos

  • Node.js 22 ou superior.
  • Um agente que controle o navegador e execute JavaScript na página: Claude in Chrome, Playwright MCP ou Chrome DevTools MCP.
  • De preferência, uma conta de teste (trial) do produto, logada num perfil separado do Chrome.

Instalação

Claude Code (plugin)

No terminal:

claude plugin marketplace add alextnetto/res
claude plugin install res@res

Dentro de uma sessão do Claude Code os comandos são /plugin marketplace add alextnetto/res e /plugin install res@res. Depois, abra uma sessão nova.

Outros agentes (skill em disco)

git clone https://github.com/alextnetto/res.git && mkdir -p ~/.claude/skills && cp -R res/skills/reverse-engineering-saas ~/.claude/skills/

Ajuste o destino para a pasta de onde o seu agente lê as skills.

Atualizar

claude plugin marketplace update res
claude plugin update res@res

Comandos e uso

  1. Crie uma conta de teste do produto com um e-mail seu, faça login num perfil separado do Chrome e conecte a ferramenta de navegador do agente a esse perfil.
  2. Peça ao agente, por exemplo:
Study Pipedrive so my team can rebuild it for the Brazilian market.
Use the trial profile, and don't ask me anything until you're done.

O agente cria a pasta re-<produto>/ e, ao terminar, entrega o REPORT.html e o re-<produto>-handoff-<data>.zip. Para retomar depois, abra uma sessão na mesma pasta e diga "Continue the Pipedrive study."

Os scripts também funcionam sem agente, para criar, validar, gerar relatório ou empacotar uma base:

node skills/reverse-engineering-saas/scripts/init-kb.mjs --product "Acme CRM" --git   # cria a base de conhecimento
node skills/reverse-engineering-saas/scripts/check-kb.mjs re-acme-crm                 # valida a base
node skills/reverse-engineering-saas/scripts/build-report.mjs re-acme-crm             # gera o REPORT.html
node skills/reverse-engineering-saas/scripts/pack-kb.mjs re-acme-crm                  # gera o zip de entrega

Cada script mostra as opções com --help.

Níveis de segurança

Nível Ambiente O que o agente pode alterar
L1 Conta trial em perfil separado do navegador Tudo, exceto ações externas e irreversíveis
L2 Workspace novo e vazio no seu login Dados de teste e configuração desse workspace
L3 Uma lista, projeto ou pipeline de sandbox dentro da produção Só dados de teste dentro desse container
L4 Produção, só observação Nada

Em todos os níveis o agente nunca envia mensagens ou convites, não menciona outras pessoas, não mexe em cobrança, não cria contas e não digita senhas.

Quando usar

  • Entender a fundo um SaaS concorrente ou de referência antes de construir algo parecido (ex.: um CRM para o mercado brasileiro).
  • Gerar requisitos, regras e testes de paridade para entregar a desenvolvedores ou a um agente de código.
  • Levantar o que pode travar o lançamento de um clone: integrações com aprovação, licenças, certificações.

Observações

  • Uso responsável: use só em contas suas ou que você tem autorização para examinar. Muitos termos de uso proíbem engenharia reversa ou uso para concorrência; a decisão e o risco jurídico são seus. Recrie a partir do comportamento, sem copiar código, ícones, logos ou textos.
  • Use conta de teste em perfil separado do Chrome. Assim o agente não alcança a sua conta de produção nem por engano.
  • Funciona mal com apps desktop ou mobile, porque precisa do DOM e da rede. Para binários, Electron e APKs, use o REA: ele mostra com o que o produto é feito, e o RES mostra como funciona para o usuário.
  • Projeto jovem (versão 0.4.0, poucas estrelas), mas com dois estudos completos publicados como exemplo: ClickUp e Pipedrive.
