O que é

É o conjunto de skills que Matt Pocock usa no dia a dia, tirado do diretório .agents dele. A proposta é fazer engenharia de verdade, "não vibe coding": em vez de frameworks que controlam todo o processo (GSD, BMAD, Spec-Kit), as skills são pequenas, fáceis de adaptar e componíveis, e funcionam com qualquer modelo.

O README organiza o conteúdo em torno de quatro falhas comuns dos agentes: (1) o agente não fez o que você queria, resolvido com sessões de "grilling"; (2) o agente é verboso demais, resolvido com uma linguagem compartilhada (glossário e ADRs); (3) o código não funciona, resolvido com ciclos de feedback e TDD; (4) o código virou uma "bola de lama", resolvido com atenção contínua ao design.

As skills se dividem em duas pastas: engineering (código) e productivity (ferramentas gerais). Há skills invocadas pelo usuário (digitadas como /nome, orquestram) e skills invocadas pelo modelo (disciplinas reutilizáveis que o agente também aciona sozinho).

Skills em destaque: grill-me e grilling

As duas ficam em skills/productivity/ e são, segundo o autor, as skills mais populares do repositório.

  • /grill-me (invocada pelo usuário): você é entrevistado de forma implacável sobre um plano ou design até resolver todos os ramos da "árvore de decisões". Ela é só um atalho: o arquivo SKILL.md tem frontmatter disable-model-invocation: true e manda chamar a skill grilling.
  • grilling (invocada pelo modelo): é a primitiva de entrevista reutilizável por trás de grill-me, grill-with-docs, triage, wayfinder e improve-codebase-architecture. Seu SKILL.md define o método:
    • mapear o plano como uma árvore de decisões, onde cada decisão gera outras;
    • trabalhar em rodadas: a "fronteira" são as decisões cujos pré-requisitos já foram resolvidos, e todas as perguntas da fronteira são feitas de uma vez, numeradas, cada uma com a resposta recomendada pelo agente (redigidas para que "sim" aceite a recomendação);
    • fatos do ambiente (arquivos, ferramentas) são buscados pelo próprio agente, via subagente, sem perguntar ao usuário; as decisões são do usuário;
    • a sessão termina quando a fronteira está vazia, e o agente não age até você confirmar o entendimento compartilhado.

Use essas skills toda vez que for fazer uma mudança: elas alinham você e o agente antes de começar.

  • Engineering (modelo): prototype, diagnosing-bugs, research, tdd, domain-modeling, codebase-design, code-review, pr, wizard.

  • Productivity (modelo): grilling, writing-for-agents.

  • Funciona com Claude Code, Codex, GitHub Copilot, Gemini CLI e outros agentes.

Pré-requisitos

  • Um agente de código compatível (Claude Code, Codex, Copilot, Gemini CLI, Cursor, etc.).
  • Para o instalador manual npx skills, Node.js/npm.

Instalação

Escolha um método por agente (instalar plugin e skills.sh ao mesmo tempo duplica as skills).

Claude Code

claude plugin install mattpocock-skills@claude-plugins-official

Atualiza sozinho por padrão.

Codex

codex plugin marketplace add mattpocock/skills
codex plugin add mattpocock-skills@mattpocock

GitHub Copilot (CLI e VS Code)

copilot plugin marketplace add mattpocock/skills
copilot plugin install mattpocock-skills@mattpocock

Depois, adicione uma vez ao ~/.copilot/settings.json:

{
  "extraKnownMarketplaces": {
    "mattpocock": { "source": { "source": "github", "repo": "mattpocock/skills" }, "autoUpdate": true }
  }
}

No VS Code, rode Chat: Install Plugin From Source e informe https://github.com/mattpocock/skills.

Gemini CLI (atualização manual)

gemini skills install https://github.com/mattpocock/skills.git --path skills/engineering
gemini skills install https://github.com/mattpocock/skills.git --path skills/productivity

Qualquer outro agente (arquivos editáveis)

npx skills@latest add mattpocock/skills -a <agent>

Agentes citados: cursor, opencode, devin, windsurf, amp, pi (omita -a para escolher). Inclua a skill setup-matt-pocock-skills. Para atualizar: npx skills@latest update.

Configuração inicial

Em cada repositório, rode uma vez /setup-matt-pocock-skills. Ela pergunta qual issue tracker você usa (GitHub, GitLab, arquivos locais), quais labels aplica na triagem e onde salvar os documentos.

Comandos e uso

/grill-me                 # entrevista sobre um plano ou design (uso geral)
/grill-with-docs          # grilling que também atualiza GLOSSARY.md e ADRs
/to-spec                  # transforma a conversa em um spec publicado no tracker
/to-tickets               # quebra um plano em tickets "tracer bullet" com dependências
/implement                # implementa spec ou tickets usando /tdd e /code-review
/triage                   # move issues por uma máquina de estados de triagem
/improve-codebase-architecture   # procura oportunidades de aprofundar módulos
/handoff                  # compacta a conversa em um documento para outro agente
/wait-what                # reexplica, em linguagem simples, algo que não ficou claro

Quando usar

  • Antes de qualquer mudança relevante, para alinhar expectativas com o agente (grill-me).
  • Para reduzir a verbosidade do agente criando um glossário do domínio.
  • Para fluxos de planejamento até implementação: spec, tickets, TDD e revisão.
  • Para diagnosticar bugs difíceis com um ciclo disciplinado (diagnosing-bugs).

Observações

  • O repositório tem muitas skills: instale conscientemente para não carregar contexto desnecessário.
  • Algumas skills de engenharia dependem de /setup-matt-pocock-skills ter sido executada no repositório.
  • O autor mantém uma newsletter para acompanhar mudanças.
