O que é

A Proxmox Skill une, em uma única pasta, as instruções de uma skill para o Codex (SKILL.md) e um cliente real da API do Proxmox VE (scripts/proxmox_vm.py), executado com uv run. Permite inspecionar o cluster, iniciar guests, criar VMs, clonar templates e provisionar containers LXC.

O fluxo recomendado é "inspecionar antes de alterar": o agente lista nós, IDs livres, storages e templates antes de qualquer operação que modifique algo. As credenciais ficam em um .env local, e só o .env.example é publicado.

O helper usa apenas a biblioteca padrão do Python, normaliza root para root@pam, gerencia o ticket de autenticação e envia o cabeçalho CSRF automaticamente. É um projeto pequeno (~10 estrelas), criado e validado por um único mantenedor.

Principais recursos

  • Inspeção de nós, próximo VMID livre, VMs e containers.
  • QEMU: iniciar, criar VM em branco e clonar a partir de template (clone completo com --full).
  • LXC: criar e iniciar containers a partir de templates do Proxmox.
  • --wait para aguardar o resultado real da tarefa, em vez do ID da tarefa na fila.
  • Credenciais lidas de .env direto do disco (sem source no shell).
  • Scripts de exemplo não destrutivos: cluster_probe.py e guest_snapshot.py.
  • Documentação em inglês e japonês.

Pré-requisitos

  • Um servidor Proxmox VE acessível, com usuário e senha (a skill usa autenticação por ticket).
  • uv instalado, para rodar o script.
  • Codex (ou outro agente que leia o SKILL.md).

Instalação

O README não descreve um comando de instalação como plugin; o uso é clonar o repositório e configurar o .env:

git clone https://github.com/Sunwood-ai-labs/proxmox-skill.git
cd proxmox-skill
Copy-Item .env.example .env   # no Linux/macOS: cp .env.example .env
# edite o .env com host, usuário e senha do Proxmox

Para o agente usar como skill, a pasta precisa estar no diretório de skills do cliente. O README não detalha esse passo; consulte a documentação do seu agente.

Comandos e uso

Os comandos do README usam a sintaxe do PowerShell; em outros shells, troque .\scripts\... por ./scripts/....

uv run .\scripts\proxmox_vm.py nodes                  # lista os nós do cluster
uv run .\scripts\proxmox_vm.py nextid                 # próximo VMID livre
uv run .\scripts\proxmox_vm.py list-vms --node pve    # lista VMs de um nó
uv run .\scripts\proxmox_vm.py list-cts --node pve    # lista containers LXC de um nó

Criar uma VM em branco:

uv run .\scripts\proxmox_vm.py create `
  --node pve --vmid 220 --name app-220 `
  --memory 4096 --cores 4 --bridge vmbr0 `
  --storage local-lvm --disk-gb 32 --wait

Clonar de um template:

uv run .\scripts\proxmox_vm.py clone `
  --node pve --source-vmid 9000 --newid 221 `
  --name app-221 --full --wait

Criar e iniciar um container LXC:

uv run .\scripts\proxmox_vm.py create-ct `
  --node pve --vmid 230 --hostname codex-230 `
  --ostemplate local:vztmpl/ubuntu-24.04-standard_24.04-2_amd64.tar.zst `
  --storage local-lvm --memory 512 --swap 512 --cores 1 `
  --disk-gb 8 --bridge vmbr0 --ip dhcp `
  --wait --start-after-create

Exemplos de prompt para o agente: "liste os nós e os guests do meu Proxmox", "clone o template 9000 para uma nova VM chamada app-221 e aguarde terminar".

Quando usar

  • Dar a um agente a capacidade de provisionar VMs e containers em um homelab ou servidor Proxmox próprio.
  • Automatizar clonagem de templates e criação de LXC com verificação prévia.
  • Partir de um cliente simples da API do Proxmox, sem dependências além do Python.

Observações

  • As operações criam e alteram máquinas reais. Revise o que o agente vai executar, use um usuário com o mínimo de permissões e teste primeiro em um ambiente que possa ser descartado.
  • A senha fica em texto no .env: nunca versione o arquivo e não o compartilhe com o agente além do necessário.
  • A validação em ambiente real relatada no README cobre apenas o caminho LXC (criar, iniciar, confirmar running, parar e confirmar stopped); os fluxos de VM não têm validação equivalente descrita.
  • Projeto pequeno e com último push em mar/2026; o suporte a outros agentes além do Codex não é descrito.
