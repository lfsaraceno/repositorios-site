App Store Compliance

Guia e verificador para evitar rejeição na App Store e no Google Play: 124 padrões de rejeição com a diretriz e a correção, checagem do privacy manifest e do formulário Data safety, 115 prazos de leis (EU AI Act, DSA, COPPA, leis de idade) e uma skill com hook que barra o envio quando há risco crítico.

O que é

Uma rejeição custa uma semana: você envia, espera a revisão, recebe uma linha de motivo, adivinha a correção e envia de novo. Este projeto faz a checagem antes do envio.

O guard (app-store-compliance-guard.sh) varre o projeto iOS ou Android e lista os riscos, os críticos primeiro, com o arquivo e a linha. No fim dá um veredito:

  • BLOCKED.: há risco crítico. Corrija cada linha [CRITICAL] seguindo a linha fix. e rode de novo.
  • CLEAR.: nenhum risco crítico no código. Não é aprovação; faltam as checagens que um scan não vê (conta, listagem, notas para o revisor).
  • NOT CHECKED.: não achou projeto iOS ou Android na pasta.

O autor dá prioridade às duas causas que mais reprovam hoje: uma conta de demonstração que funciona com o backend no ar, e uma declaração de privacidade que bate com o que o app faz de verdade, incluindo cada SDK.

Principais recursos

  • 124 padrões de rejeição em data/rejection-patterns.json, cada um com a diretriz da Apple ou a política do Google e a correção.
  • Guard que roda sozinho ou como hook: dispara antes de fastlane, eas submit, gradle bundleRelease e xcrun altool e barra o envio se houver risco crítico.
  • Skill de auditoria completa e o comando /app-store-audit (Claude Code, Gemini CLI e OpenCode).
  • Instalador para Claude Code, Codex, Gemini CLI, OpenCode, Cursor, Copilot, Grok, Qwen Code, Kimi Code, Factory Droid, Auggie e Windsurf.
  • 115 prazos regulatórios por região (UE, EUA, Reino Unido, Austrália e outros), conferidos a cada execução do guard.
  • Auditoria da listagem na loja (metadata-audit.py), de acessibilidade, de prontidão de release e monitores das mudanças de regras da Apple, do Google e de leis.
  • Checklist em linguagem simples para quem não programa, playbook de recurso para app já rejeitado e modelo de notas para o revisor.
  • Cobre também Flutter, React Native, Expo, Capacitor, Unity, .NET MAUI e Kotlin Multiplatform.
  • As fontes citadas são verificadas por script (verify-citations.py), que detecta links inventados que respondem 200.

Pré-requisitos

  • git e bash (no Windows, Git Bash).
  • python3 para os outros agentes além do Claude Code e para os scripts de auditoria e monitoramento.
  • node só para a verificação do plugin do OpenCode.

Instalação

Checagem única, sem instalar nada e sem alterar o app:

git clone https://github.com/mjmirza/app-store-compliance ~/repositories/app-store-compliance
bash ~/repositories/app-store-compliance/agent-os/hooks/app-store-compliance-guard.sh "/path/to/your/app"

No agente de código (hook, skill e comando antes de todo envio):

bash ~/repositories/app-store-compliance/scripts/install.sh              # Claude Code
bash ~/repositories/app-store-compliance/scripts/install.sh --tool all   # todos os agentes encontrados

Depois, reinicie o Claude Code. No Codex, rode /hooks e aprove o hook novo. A instalação termina com Install verified. só depois de testar que o hook barra um envio.

Comandos e uso

install.sh --dry-run     # mostra o que seria escrito, sem escrever
install.sh doctor        # confere a instalação e prova que o hook bloqueia
install.sh uninstall     # remove guard, comando e hook (mantém seus outros hooks)
git -C ~/repositories/app-store-compliance pull   # atualizar as regras

Outras checagens, rodadas na pasta do playbook:

cd ~/repositories/app-store-compliance
python3 scripts/release-audit.py /path/to/your/app --metadata ./metadata   # gera RELEASE-READINESS-REPORT.md
python3 scripts/accessibility-audit.py /path/to/your/app
python3 scripts/deadline-checker.py --brief # prazos legais dos próximos 90 dias
python3 scripts/monitor.py --project /path/to/your/app   # mudanças da Apple pelo feed oficial

Quando usar

  • Antes de enviar um app iOS ou Android, principalmente um feito com IA às pressas.
  • Depois de uma rejeição, para achar a causa e montar o recurso.
  • Para deixar o agente de código impedido de enviar um app que seria rejeitado.

Observações

  • Não garante aprovação. O scan não vê se a conta de desenvolvedor está ativa, se os contratos estão aceitos nem o que foi declarado no App Store Connect ou no Play Console. Faça essas partes pelo checklist.
  • Licença: grátis para pessoas, ONGs, escolas, governo e empresas com até US$ 20 milhões de receita anual. Acima disso, royalty de 0,5% sobre o que passar do limite, com teto de US$ 250 mil por ano. Revender o playbook como produto exige acordo à parte, e treinar IA com o repositório exige outra licença. Versões até 24/08/2026 continuam MIT (código) e CC BY 4.0 (conteúdo).
  • O hook entra na configuração do agente (por exemplo ~/.claude/settings.json), e o instalador faz backup do arquivo antes. Confira com --dry-run.
  • Os monitores, exceto o monitor.py, usam anúncios de exemplo, a menos que você passe --live. Trate essa saída como exemplo, não como notícia.
  • O README sugere um prompt para o agente instalar tudo; ele pede para o agente mostrar os links para dar estrela, mas nunca agir na sua conta do GitHub.
  • Para lei brasileira, use junto as LGPD Skills. Para a página na loja (ASO), o Marketing Skills tem a skill aso.
