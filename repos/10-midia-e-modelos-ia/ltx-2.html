O que é

O LTX-2 é um modelo de base de áudio e vídeo (arquitetura DiT) que gera vídeo e som sincronizados num único modelo: falas, ruídos e trilha saem junto com a imagem. A versão recomendada é o LTX-2.5 (transformer de 22B parâmetros com encoder de texto Gemma 4 12B ajustado); o LTX-2.3 continua suportado.

Este repositório é um monorepo com três pacotes: ltx-core (implementação do modelo e da inferência), ltx-pipelines (pipelines de alto nível: texto para vídeo, imagem para vídeo, áudio para vídeo, vídeo para vídeo, dublagem, HDR) e ltx-trainer (treino de LoRA, fine-tuning completo e IC-LoRA).

Roda localmente, mas exige GPU robusta e cerca de 66 GiB só de pesos no pacote básico. Para usar no ComfyUI existe o ComfyUI-LTXVideo.

Principais recursos

  • DistilledPipeline: texto/imagem para vídeo mais rápido (8 passos no estágio 1, 4 no estágio 2); o ponto de partida.
  • DFR (Diffusion Fidelity Rendering): qualidade de produção, com keyframes gerados e passe de detalhamento; padrão 1024×1536 a 24 fps, até UHD 4K (--width 3840 --height 2176) e 2x/4x fps com o upscaler temporal.
  • A2VidPipelineTwoStage: vídeo condicionado a um arquivo de áudio.
  • DubItPipeline: dublagem que reescreve a fala mantendo a identidade do falante e o movimento dos lábios.
  • RetakePipeline: regenera só um trecho de tempo de um vídeo existente.
  • ICLoraPipeline: vídeo para vídeo e imagem para vídeo; HDRICLoraPipeline: converte SDR em HDR (BT.2020/HLG e sequência EXR ACEScct).
  • HDR/EXR nativo com --hdr {SRGB_LINEAR,ACESCG,ACESCCT,ACES2065_1}.
  • Treino de LoRA, IC-LoRA e fine-tuning completo com o ltx-trainer.
  • Otimizações: quantização FP8, offload para CPU ou disco, FlashAttention 3/4, aprimoramento automático de prompt (enhance_prompt).

Pré-requisitos

  • GPU NVIDIA com bastante VRAM (o README não fixa um mínimo; com pouca memória use FP8 e offload).
  • uv para instalar as dependências.
  • Conta no Hugging Face com os termos do modelo aceitos e um token Read (tokens fine-grained precisam do escopo "read gated repos").
  • ~66 GiB de disco para os pesos básicos do LTX-2.5.
  • Windows e macOS funcionam: o extra natten (só Linux + CUDA) é ignorado automaticamente e o decoder usa Triton ou implementação eager.

Instalação

1. Clonar e instalar

git clone https://github.com/Lightricks/LTX-2.git
cd LTX-2
uv sync --extra natten

2. Baixar os modelos (~66 GiB)

hf auth login
hf download Lightricks/LTX-2.5 \
    diffusion_models/ltx-2.5-22b-distilled-transformer-bf16.safetensors \
    text_encoders/gemma4-12b-with-proj-ltx-2.5-bf16.safetensors \
    vae/ltx-2.5-video-vae-bf16.safetensors \
    vae/ltx-2.5-audio-vae-bf16.safetensors \
    latent_upscale_models/ltx-2.5-latent-spatial-upscaler-x2-bf16-1.0.safetensors \
    --local-dir models/ltx-2.5

Erro 401/403: aceite os termos do modelo no Hugging Face e entre com um token Read.

3. (Opcional) IC-LoRA de detalhamento para o DFR

hf download Lightricks/LTX-2.5-22b-IC-LoRA-Pixel-Spatial-Upscaler \
    ltx-2.5-22b-ic-lora-pixel-spatial-upscaler-x2-1.0.safetensors \
    --local-dir models/ltx-2.5/loras

Comandos e uso

Gerar vídeo rápido (DistilledPipeline)

uv run python -m ltx_pipelines.distilled \
    --transformer-path       models/ltx-2.5/diffusion_models/ltx-2.5-22b-distilled-transformer-bf16.safetensors \
    --text-encoder-path      models/ltx-2.5/text_encoders/gemma4-12b-with-proj-ltx-2.5-bf16.safetensors \
    --video-vae-path         models/ltx-2.5/vae/ltx-2.5-video-vae-bf16.safetensors \
    --audio-vae-path         models/ltx-2.5/vae/ltx-2.5-audio-vae-bf16.safetensors \
    --spatial-upsampler-path models/ltx-2.5/latent_upscale_models/ltx-2.5-latent-spatial-upscaler-x2-bf16-1.0.safetensors \
    --num-frames 121 \
    --seed 42 \
    --output-path output.mp4 \
    --prompt "<descrição detalhada da cena>"

Qualidade de produção (DFR)

Mesmo comando com o módulo ltx_pipelines.dfr_pipeline e o argumento extra --detailing-lora models/ltx-2.5/loras/ltx-2.5-22b-ic-lora-pixel-spatial-upscaler-x2-1.0.safetensors. Não use o transformer completo (dev) no DFR.

Pouca VRAM

--quantization fp8-cast --offload cpu     # ou --offload disk

Em GPUs Hopper ou mais novas com FP8 nativo e checkpoints FP8: --quantization fp8-scaled-mm.

Ajuda de qualquer pipeline

python -m ltx_pipelines.ti2vid_two_stages --help

Como escrever o prompt

Um parágrafo único, em ordem cronológica, com até 200 palavras, como um diretor de fotografia descrevendo a cena: ação principal numa frase; detalhes de movimento e gestos; aparência de personagens e objetos; ambiente; ângulo e movimento de câmera; luz e cores; mudanças ou eventos repentinos. Inclua falas e sons, já que o modelo gera áudio. Guia oficial: https://ltx.io/blog/prompting-guide-for-ltx-2.

Quando usar

  • Gerar vídeos curtos com fala e som sincronizados localmente, sem pagar por API de vídeo.
  • Pipelines de pós-produção: dublagem com sincronia labial, refazer trechos de um vídeo, converter SDR para HDR.
  • Treinar LoRAs de estilo, personagem ou controle (IC-LoRA) sobre o LTX-2.
  • Integrar geração de vídeo a um fluxo próprio em Python ou ao ComfyUI.

Observações

  • Licença dos modelos: o código é Apache 2.0, mas os pesos seguem a LTX-2.x Community License (2.5) ou a LTX-2 Community License (2.3). Empresas (contando grupo econômico) com receita anual a partir de US$ 10 milhões precisam de licença paga para qualquer uso que não seja estritamente não comercial (contato: licensing@ltx.io). Pessoas físicas em projetos pessoais e empresas menores podem usar, respeitando as restrições de uso do anexo da licença.
  • Hardware pesado: transformer de 22B mais encoder de 12B; espere precisar de GPU de alta memória ou de quantização FP8 e offload.
  • O LTX-2.3 usa checkpoints monolíticos e encoder Gemma 3 baixado à parte (licença do Google); arquivos e LoRAs não são intercambiáveis entre 2.3 e 2.5.
  • Para uma interface web pronta com pouca VRAM, que roda LTX-2/2.3/2.5 entre outros modelos, veja o WanGP. O OpenMontage usa o LTX como um dos provedores locais de vídeo.
