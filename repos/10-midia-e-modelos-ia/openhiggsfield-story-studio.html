OpenHiggsfield Story Studio

Estúdio auto-hospedável que transforma um personagem e uma história de um minuto em um curta: você escolhe entre 50 personagens ou envia o seu, revisa seis cenas e a estimativa de custo e gera os clipes com a sua própria conta no fal ou no Higgsfield, recebendo um MP4 montado.

O que é

Um "estúdio de personagem para filme". O fluxo é guiado: personagem, roteiro de um minuto, seis cenas com direção de narração, estimativa de custo e, depois da sua aprovação, a geração de cada cena no provedor que você conectou. No fim, o FFmpeg junta os clipes num MP4.

Não roda modelos localmente: a geração é feita e cobrada pelo provedor (fal ou Higgsfield) com as suas credenciais. O projeto diz não ter ligação com o Higgsfield.ai.

É um projeto diferente do OpenHiggsfield AI, que é um estúdio de prompt único com 38 modelos.

Principais recursos

  • Galeria de 50 personagens e envio de imagem própria.
  • Rascunhos privados, roteiro por cena, direção de narração e estimativa de custo antes de gerar.
  • Conexão com fal e Higgsfield, com as credenciais criptografadas no servidor.
  • Progresso por cena, prévia dos clipes e MP4 final montado.
  • Contas e workspaces isolados, login por link mágico no e-mail (via Resend) e Google opcional.
  • Tema claro e escuro, interface responsiva.

Pré-requisitos

  • Docker com Compose, ou Node.js 24+ e FFmpeg no PATH.
  • Conta e chave no fal ou no Higgsfield (a geração é paga).
  • Para uso público: HTTPS e uma chave do Resend para enviar os e-mails de login.

Instalação

git clone https://github.com/thehiggsfieldai/OpenHiggsfield.git
cd OpenHiggsfield
cp .env.example .env
# Gere o segredo de autenticação:
node -e "console.log(require('node:crypto').randomBytes(48).toString('hex'))"
# No .env, defina BETTER_AUTH_SECRET, PUBLIC_ORIGIN, RESEND_API_KEY e EMAIL_FROM.
# Use SIGNUP_EMAILS para convidados ou ALLOW_SIGNUP=true para cadastro aberto.
docker compose up --build -d

Abra http://localhost:3000, entre e conecte o provedor em Connections. O compose.yaml publica a porta só em 127.0.0.1, com contêiner somente leitura e 1 GB de memória.

Desenvolvimento local:

npm ci
npm ci --prefix apps/story-studio
npm run dev
# Em outro terminal:
npm --prefix apps/story-studio run dev

Abra http://127.0.0.1:5193. A tela de e-mail oferece um link de login de teste, que só funciona em localhost.

Comandos e uso

npm run build
npm test
node scripts/test-story-studio.mjs
node scripts/test-story-films.mjs --fal --recommended

Os testes de provedor usam requisições simuladas e não compram gerações.

Quando usar

  • Fazer curtas com um personagem fixo para redes sociais, com custo estimado antes de gerar.
  • Hospedar um estúdio de vídeo com IA para uma equipe, cada um com o seu workspace.

Observações

  • Origem da interface: o UPSTREAM.json diz que a interface veio do projeto ilkerzg/storycast, que não tem licença publicada. A permissão para redistribuir como MIT está registrada como "não verificada de forma independente". Confirme antes de usar comercialmente.
  • Nome parecido com o da marca: a conta foi criada em set/2026, tem um único repositório e usa os domínios thehiggsfield.ai e openhiggsfield.com, mas diz não ter relação com o Higgsfield.ai. Ao colar a sua chave do Higgsfield, prefira a instância que você mesmo hospeda.
  • As chaves ficam criptografadas em repouso, não de ponta a ponta. Faça backup do volume de dados, que inclui a chave de criptografia.
  • Apagar um rascunho não apaga os filmes já gerados.
  • A publicação em galeria pública e os links de compartilhamento ainda não estão completos. A estimativa de custo não é a fatura final do provedor.
  • Os personagens incluídos não trazem direito sobre nomes, marcas ou rostos de terceiros.
  • Pouca atividade: o último commit é de set/2026.
