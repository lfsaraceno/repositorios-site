O que é

O PersonaPlex é um modelo de fala para fala, com cerca de 7 bilhões de parâmetros. Não há pipeline de transcrição, LLM e síntese: ele ouve o áudio e responde em áudio diretamente, com baixa latência. Assim, a conversa soa natural, com interrupções, pausas e "aham".

É baseado na arquitetura e nos pesos do Moshi (Kyutai). A novidade é o controle de persona:

  • um prompt de texto define quem o modelo é (professor, atendente de uma empresa, personagem);
  • um prompt de voz define como ele soa.

Principais recursos

  • Conversa full-duplex em tempo real por uma interface web.
  • Papel por texto: o modelo foi treinado para assistente e para atendimento ao cliente. O prompt descreve a empresa, o nome do atendente e as informações que ele deve usar.
  • Vozes prontas:
    • naturais: NATF0–NATF3 e NATM0–NATM3;
    • variadas: VARF0–VARF4 e VARM0–VARM4.
  • Conversas sem fim: o prompt de sistema fica fixo no contexto, mas a memória da conversa cobre só os últimos ~2,5 minutos.
  • Modo offline: processa um .wav de entrada e gera o .wav de resposta, para testes.
  • --cpu-offload, para GPUs com pouca memória.

Pré-requisitos

  • GPU NVIDIA com bastante memória (o README não diz quanto). Sem ela, use --cpu-offload ou PyTorch só de CPU no modo offline.
  • Biblioteca do codec Opus (libopus-dev no Debian/Ubuntu, opus-devel no Fedora).
  • Conta no Hugging Face, com a licença do modelo aceita e um token de acesso.

Instalação

git clone https://github.com/NVIDIA/personaplex.git
cd personaplex
sudo apt install libopus-dev
pip install moshi/.

Em GPUs Blackwell, instale também o PyTorch para CUDA 13:

pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu130

Aceite a licença em huggingface.co/nvidia/personaplex-7b-v1 e exporte o seu token na variável HF_TOKEN.

Comandos e uso

Servidor com interface web (certificado SSL temporário):

SSL_DIR=$(mktemp -d); python -m moshi.server --ssl "$SSL_DIR"
SSL_DIR=$(mktemp -d); python -m moshi.server --ssl "$SSL_DIR" --cpu-offload   # GPU com pouca memória

Abra https://localhost:8998 no navegador.

Offline (arquivo de entrada e de saída):

python -m moshi.offline \
  --voice-prompt "NATM1.pt" \
  --text-prompt "$(cat assets/test/prompt_service.txt)" \
  --input-wav "assets/test/input_service.wav" \
  --seed 42424242 \
  --output-wav "output.wav" \
  --output-text "output.json"

Exemplo de prompt de atendimento, no estilo do README:

You work for CitySan Services which is a waste management and your name is Ayelen Lucero. Information: ...

Quando usar

  • Pesquisar ou prototipar agentes de voz que conversam de forma natural.
  • Testar atendimento por voz com persona definida (restaurante, aluguel, suporte).
  • Comparar com pipelines tradicionais de transcrição, LLM e síntese de voz.
  • Comparação no catálogo: o VoiceStudio é focado em gerar e clonar vozes. O PersonaPlex é um modelo de conversa em tempo real.

Observações

  • Foco em inglês. O treino usa conversas sintéticas e o corpus Fisher English. Português e outros idiomas não são citados no README.
  • Licença dos pesos: o código é MIT, mas os pesos seguem a NVIDIA Open Model License, que é preciso aceitar no Hugging Face. Leia as condições antes de uso comercial.
  • Voz e identidade: condicionar o modelo com a voz de uma pessoa real exige o consentimento dela. A voz é dado pessoal na LGPD, e imitar alguém pode configurar fraude.
  • Servidor exposto: o moshi.server usa certificado temporário e não tem login. Não o deixe aberto na internet.
  • Memória limitada: em conversas longas, o modelo esquece o que foi dito há mais de ~2,5 minutos. Só o prompt de sistema fica fixo.
  • Projeto de pesquisa, sem releases no GitHub.
