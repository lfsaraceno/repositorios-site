O que é

Assistentes de código são poderosos, mas imprevisíveis quando os requisitos vivem só no histórico do chat. O OpenSpec adiciona uma camada de specs em Markdown, de modo que humano e IA alinham o que será feito antes de escrever código.

Cada mudança ganha uma pasta própria em openspec/changes/<nome>/ com proposal.md, specs/, design.md e tasks.md. Ao concluir, a mudança é arquivada e as specs são atualizadas. A filosofia é fluida em vez de rígida, iterativa em vez de cascata, e pensada para código existente (brownfield), de projetos pessoais a empresas.

Funciona com mais de 30 ferramentas de IA por meio de comandos slash ou skills.

Principais recursos

  • Fluxo /opsx:explore, /opsx:propose, /opsx:apply e /opsx:archive (perfil core, que inclui também update e sync).
  • Specs em Markdown simples, com requisitos e cenários (WHEN/THEN).
  • Perfil expandido opcional: new, continue, ff, verify, bulk-archive, onboard.
  • Sem fases rígidas: qualquer artefato pode ser atualizado a qualquer momento.
  • Mais de 30 ferramentas suportadas (Claude Code, Cursor, Codex, Gemini CLI, Copilot, Amazon Q, Kimi Code e outras).
  • Stores (beta): planejamento em um repositório próprio, compartilhado entre repos e times.
  • Esquemas da comunidade e perfis customizáveis.
  • O próprio OpenSpec é construído com OpenSpec.

Pré-requisitos

  • Node.js 20.19.0 ou superior (o Homebrew instala como dependência).
  • Um assistente de código suportado.

Instalação

npm install -g @fission-ai/openspec@latest

No macOS ou Linux, também via Homebrew:

brew install openspec

Há ainda pnpm, yarn, bun e Nix (veja opções de instalação). Depois, no projeto:

cd seu-projeto
openspec init

Você escolhe as ferramentas e o init imprime a forma correta dos comandos para elas. Para atualizar:

npm install -g @fission-ai/openspec@latest
openspec update      # dentro de cada projeto, regenera as instruções dos agentes

Comandos e uso

/opsx:explore

Parceiro de raciocínio sem compromisso: lê o código e pesa opções antes de planejar.

/opsx:propose add-dark-mode

Cria a pasta da mudança com proposal, specs, design e tasks.

/opsx:apply

Implementa as tarefas.

/opsx:archive

Arquiva a mudança e atualiza as specs.

openspec config profile

Seleciona o perfil de workflow (por exemplo, o expandido); aplique com openspec update.

A grafia do comando varia por ferramenta (consulte docs/supported-tools.md):

Ferramenta Como digitar
Claude Code, Gemini CLI, CodeBuddy, Crush, Qoder /opsx:propose
Cursor, GitHub Copilot e a maioria das demais /opsx-propose
Amazon Q Developer @opsx-propose
Codex $openspec-propose (só skills; /openspec-... não é reconhecido)
Kimi Code /skill:openspec-propose
Ferramentas só com skills (Hermes, Zed Agent, Mistral Vibe etc.) /openspec-<skill>

Quando usar

  • Projetos existentes em que mudanças precisam de proposta e specs revisáveis.
  • Times que querem uma fonte única de verdade para requisitos entre vários repositórios.
  • Quando você quer previsibilidade da IA sem a cerimônia de metodologias mais pesadas.

Observações

  • Recomenda-se modelos de raciocínio forte (o README cita Codex 5.5 e Opus 4.7) e boa higiene de contexto: limpe o contexto antes de implementar.
  • Telemetria anônima (apenas nome do comando e versão), desativada em CI. Para desligar: openspec config set telemetry.enabled false ou OPENSPEC_TELEMETRY=0 / DO_NOT_TRACK=1.
  • Stores estão em beta.
  • O README compara com o Spec Kit (mais pesado) e o Kiro (preso a IDE); é a visão dos autores.
