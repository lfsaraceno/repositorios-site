O que é

O Spec Kit oferece processos prontos que você pode usar, personalizar ou substituir pelos seus. O principal é o Spec-Driven Development (SDD): definir o quê e o porquê antes do como, transformando requisitos em especificação, plano técnico e tarefas acionáveis, e guiando a implementação contra esses artefatos.

Além do SDD, há processos opcionais, instalados como extensões: correção de bugs (diagnosticar, consertar e verificar) e avaliação de ideias (levantar evidências até uma decisão go, precisa de esclarecimento ou descartar). Os mecanismos de extensão incluem integrações com agentes, extensões, presets, workflows, bundles e catálogos.

Você usa o CLI specify no terminal para configurar o projeto e invoca as skills /speckit-* no chat do seu agente.

Principais recursos

  • SDD completo: constituição, especificação, plano, tarefas, implementação e convergência.
  • Extensões opcionais: bug (assess, fix, test) e assess (intake, research, define, shape, decide).
  • Integrações com vários agentes de código (o exemplo usa GitHub Copilot em modo skills).
  • Presets para adaptar templates, terminologia e padrões organizacionais.
  • Workflows para automatizar prompts, comandos, gates e tarefas de shell.
  • Bundles de configurações por papel ou equipe e catálogos (inclusive privados e offline).
  • Guia para projetos existentes (brownfield) e comandos de busca como specify extension search.

Pré-requisitos

  • Python 3.11 ou superior.
  • uv.
  • Um agente de código suportado, em Linux, macOS ou Windows.

Instalação

uv tool install specify-cli
specify init my-project --integration copilot
cd my-project

Troque copilot pela chave de integração do seu agente (lista na referência de integrações). Para projetos que já têm código, siga o guia de projetos existentes. Versões fixadas, outros instaladores, CI e troubleshooting estão em Installation; para atualizar, veja Upgrade.

Depois, abra o agente na pasta do projeto.

Comandos e uso

Estas são skills do agente, digitadas no chat, uma por vez, revisando o resultado antes de seguir. Não são comandos de terminal.

/speckit-constitution Create principles focused on code quality, testing, and maintainability.

Define os princípios do projeto (uma vez por projeto).

/speckit-specify Build a photo organizer with albums grouped by date and a tile preview of each album.

Cria a especificação da funcionalidade.

/speckit-plan Use Vite with vanilla JavaScript. Keep images local and store metadata in SQLite.

Gera o plano técnico.

/speckit-tasks
/speckit-implement
/speckit-converge

Quebra em tarefas, implementa e confere a convergência; repita implement e converge até o resultado ser "Converged".

Correção de bugs:

specify extension add bug

/speckit-bug-assess "Submitting an empty password crashes the login form." slug=login-crash
/speckit-bug-fix slug=login-crash
/speckit-bug-test slug=login-crash

Avaliação de ideias:

specify extension add assess

/speckit-assess-intake "Let users work offline and sync when they reconnect." slug=offline-mode

Os relatórios ficam em .specify/bugs/<slug>/ e .specify/assessments/<slug>/.

Quando usar

  • Construir uma funcionalidade ou app com especificação, plano e tarefas explícitos.
  • Diagnosticar um bug com causa avaliada, correção delimitada e verificação registrada.
  • Decidir se uma ideia merece investimento antes de escrever código.
  • Impor padrões organizacionais por meio de presets e catálogos próprios.

Observações

  • Catálogos da comunidade não são auditorias nem endorsements: revise o código-fonte antes de instalar.
  • A sintaxe de invocação varia conforme o agente e o modo (veja a referência de integrações).
  • Exige Python e uv; o OpenSpec compara-se a ele como mais leve, mas é visão do concorrente.
